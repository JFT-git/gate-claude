# Claude Proxy Guard — сведения для службы информационной безопасности

Документ для первичной технической оценки перед внедрением. Он описывает назначение, привилегии, сетевые обращения, данные и ограничения продукта. Решение о допуске принимает организация по своим требованиям; сертификация и прохождение проверок ИБ не заявляются.

**Актуальность: 23 октября 2026 года.** В основной ветке находятся Windows 0.6.7 / macOS 0.3.3. Отдельно опубликован [кандидат Windows 0.6.9 / macOS 0.3.4 — RC1](https://github.com/JFT-git/gate-claude/releases/tag/v0.6.9-rc1), исходники которого закреплены commit [`4adfc43`](https://github.com/JFT-git/gate-claude/tree/4adfc43974ce5cf0a65392b581b94c8ac507a979). Статусы проверок ниже относятся именно к RC1. Для согласования фиксируйте версию, commit и SHA-256 конкретного устанавливаемого файла.

## 1. Назначение и состав

Guard — независимое приложение для запуска собственной локальной копии установленного Claude Desktop, проверки выходного IP, управления локальным шлюзом и просмотра доступных веб-запросов. Не связано с Anthropic. Claude Desktop и учётная запись устанавливаются/создаются отдельно; vendor runtime не включён в дистрибутив Guard.

Поддерживаются Windows 10/11 x64 и macOS 13+ universal arm64/x86_64. Linux и отдельная Windows ARM64-сборка не заявлены. Windows-режим Claude Code поддерживает Desktop 1.44121.2 и Store 4.23118.0; текущий закреплённый CLI — 2.1.317; native Git HTTPS и PowerShell поддерживаются в предусмотренной изоляции, Git Bash и Git SSH — нет.

Guard изменяет ASAR **собственной копии** Claude и её профиль. Исходная подпись Anthropic не удостоверяет модифицированную копию. Язык и часовой пояс применяются к контекстам Claude; системные язык и часовой пояс ОС не меняются.

## 2. Архитектура и границы защиты

**Windows:** обычный процесс Guard с Electron управляет локальным шлюзом и контроллером. Renderer использует `contextIsolation`, sandbox, отключённую Node integration и локальную CSP; команды передаются через проверяемый IPC. Повышенный NetworkFence устанавливает WFP-фильтры для проверенных путей EXE частной копии. GuardHost помещает runtime в Job Object. Для Code предусмотрены AppContainer без capabilities, CodeHost/CodeGate, проверенные инструменты и постоянная Workspace.

Ограничения Chat по путям EXE **не являются изоляцией всего компьютера**. Неизвестные внешние программы и обращения через системные службы находятся за этой границей. Сохранение файлов Workspace не означает шифрование данных или разрешение любых действий Claude Code.

**macOS:** SwiftUI, локальный CONNECT-шлюз, helper/process group и адаптер веб-контекстов. Системного сетевого запрета, Network Extension, полной sandbox-изоляции копии, Docker или VM нет. Native-вызовы, MCP и Cowork могут обходить прокси. Windows-механизмы защиты на macOS не переносятся.

Проверки внешнего IP периодические и зависят от внешних серверов. Временная неопределённость или смена IP замораживает процесс на 20 секунд и возобновляет его только после полного подтверждения прежнего адреса; при отсутствии восстановления выполняется graceful/forced close. Открытые потоки не сохраняются. RU, потеря WFP/PF и diagnostic failures приводят к немедленной блокировке. Мгновенный kill switch и отсутствие любого возможного обхода или утечки не гарантируются.

## 3. Права, служба и установка

Основное приложение следует запускать обычным пользователем. В текущей Windows-архитектуре постоянная auto-start служба `ClaudeProxyGuard` запускает только закреплённый NetworkFence. Первая установка и изменение privileged binaries требуют UAC; обычные сессии и app updates с неизменными совместимыми binaries не требуют повторного повышения. Удаление службы требует отдельного elevated request. Отдельно административные права нужны необязательному скрипту блокировки оригинального Claude. Изменять ACL WindowsApps для поиска Claude не требуется.

Protected helpers находятся в `%ProgramData%\Claude Proxy Guard\Service` с записью только для SYSTEM/Administrators. Privileged pipe проверяет клиентский SID через impersonation и root внутри ProfileList этого пользователя; renderer прямого доступа к pipe не имеет. Произвольный executable/args и запуск Claude службой не поддерживаются. Подробная схема и статус проверок приведены в `docs/service-integration.md`. Исторический RC1, перечисленный выше, этой службы не содержал; его прежние результаты не переносятся на новую реализацию.

Windows portable ZIP распаковывается целиком: одного EXE недостаточно. Portable сохраняет данные в профиле пользователя и при первой защищённой сессии устанавливает ту же службу с UAC. Per-user NSIS копирует приложение в каталог пользователя, после чего выполняет fail-closed service install request. Standard-user/secure-desktop lifecycle и installed A→B update требуют отдельной проверки; roaming/UNC/reparse profile paths отклоняются. macOS распространяется как `.app` в ZIP/DMG; копирование в общую `/Applications` может потребовать разрешения ОС, работа root не нужна.

## 4. Сеть и внешние зависимости

- Локальный HTTP CONNECT-шлюз: случайный TCP-порт на **127.0.0.1**. Фиксированного публичного порта управления нет.
- Управление runtime: локальные named pipes Windows либо унаследованные pipe/stdio macOS; внешний TCP debug-порт не открывается.
- HTTPS-проверки IP/страны: `ipwho.is`, `ipinfo.io`, `ipapi.co`, `api64.ipify.org`, `api.ipify.org`, `api6.ipify.org`. Запросы группы выполняются параллельно, принимаются согласованные ответы; один работающий сервис является явным fallback, противоречия блокируются.
- Внешняя DNS-метрика: случайный 32-hex поддомен `edns.ip-api.com`, только публичные сведения о DNS-ответчике. Она не влияет на запуск и не заменяет защитные DNS/WebRTC-правила.
- На Windows и macOS после установления pin hostname-запросы выполняются через `cloudflare-dns.com` и `dns.google` по HTTPS с привязкой к проверенному egress. DoH-провайдеры видят имена назначений; отказ обоих закрывает CONNECT без возврата к системному resolver.
- Windows дополнительно проверяет выход к `claude.ai` и `api.anthropic.com` через `/cdn-cgi/trace`.
- При включении Code возможна загрузка закреплённого CLI с `downloads.claude.ai`; размер и SHA-256 проверяются. Git/PowerShell поставляются проверенными sidecar-комплектами.
- Автообновление Guard загружает signed metadata и пакеты из стабильных GitHub Releases по HTTPS. Учётные данные Claude и пользовательские файлы при этом не отправляются.
- Дальнейшее подключение выполняется через выбранный SOCKS5 либо текущую сеть/VPN; на Windows поддерживается предусмотренный статический системный прокси. Имя самого SOCKS5-сервера может разрешаться локально.

Сервисы проверки получают выходной IP и обычные метаданные HTTPS; Guard не отправляет им содержимое чатов или данные аккаунта. Этот список описывает зависимости **Guard**, а не полный allowlist Claude: vendor Claude/Code, вход и пользовательские команды могут обращаться к другим узлам.

Guard не устанавливает MITM-сертификаты и не отключает production-проверку TLS. Просмотр доступных веб-данных выполняется внутри контекстов Claude после TLS. Полнота видимого трафика не гарантируется.

## 5. Настройки, секреты и журналы

**Windows:** `%APPDATA%\Claude Proxy Guard\Guard` — настройки, `diagnostics.json` до 80 событий, Profile, runtime/cache, CodeAssets/CodeBin/CodeTools и CodeState. Постоянная рабочая папка: `CodeState\Workspace`; авторизация Code находится внутри CodeState. `Guard\logs` содержит ограниченные технические JSONL/LOG с маскированием при записи. Диагностический ZIP не включает Profile, CodeState, settings, ip-memory или трафик, но как и любые журналы требует просмотра перед передачей.

**macOS:** `~/Library/Application Support/ClaudeProxyGuard` — Profile, Runtime и `Diagnostics/events.jsonl` до 80 событий. Настройки UserDefaults: домен `local.proxyguard.claude`.

Пароль SOCKS5 исключается из сохраняемых настроек Guard и остаётся в памяти. Хост, порт и логин сохраняться могут. Vendor-профили содержат собственные cookies и данные входа. Заявление о пароле прокси не распространяется на секреты внутри профиля Claude, рабочих файлов и переписки.

Доступный трафик ограничен 200 записями в памяти; экспорт сохраняется по явному выбору пользователя. Windows по умолчанию не захватывает тела, macOS включает их при отсутствии сохранённой настройки. Маскирование известных токенов не является универсальным DLP: произвольные URL, заголовки и тела могут содержать секреты.

Собственного шифрования настроек, профиля и экспорта на диске нет. Права Code настраиваются механизмами Windows; POSIX `mode` в JS сам по себе не подтверждает Windows ACL. Сырые экспорты, magic link, профили и журналы переписки нельзя прикладывать к публичным обращениям без проверки содержимого.

## 6. Телеметрия

В коде Guard не обнаружен отдельный аналитический SDK или собственный сервер телеметрии. Внешние IP-проверки, загрузки CLI, авторизация и трафик Claude являются реальными передачами данных. Собственная телеметрия Claude/Code и ОС этим утверждением не исключается. Для подготовленного PowerShell задаются `POWERSHELL_TELEMETRY_OPTOUT=1` и `POWERSHELL_UPDATECHECK=Off`.

## 7. Происхождение и фактические проверки RC1

В [RC1](https://github.com/JFT-git/gate-claude/releases/tag/v0.6.9-rc1) приложены ZIP/DMG, `SHA256SUMS.txt`, `release-manifest.json` и отчёты. Сверяйте имя файла, размер, SHA-256 и исходный commit. Контрольная сумма с той же страницы подтверждает целостность относительно опубликованного значения, но не является независимой подписью издателя.

Windows Authenticode не настроена. macOS имеет только ad-hoc codesign, без Developer ID и notarization. Сертификаты соответствия ИБ и независимый сертификационный аудит отсутствуют в опубликованных материалах.

[Отчёт RC1](https://github.com/JFT-git/gate-claude/blob/4adfc43974ce5cf0a65392b581b94c8ac507a979/Verification/ux-069.json):

- На macOS arm64: 471 успешный Node-тест, 0 ошибок, 14 Windows-native пропущены.
- 20 сценариев настоящего Electron renderer с тестовым IPC; сеть fixture отключена. Это проверка интерфейса, не WFP и не установленной службы.
- macOS: локальный suite, SwiftUI-отрисовка с тестовой моделью, сборка universal; ZIP/DMG и ad-hoc целостность проверены.
- Windows cross-build: содержимое ASAR сверено с исходниками, native/CodeTools — с закреплёнными хешами.
- **Не выполнены для RC1:** Windows-native runtime, чистый UAC, настоящий Claude/Code, установка/удаление Windows Setup, исполнение macOS на Intel и ручная проверка Narrator/VoiceOver.

Результаты других версий не подменяют проверки выбранного пакета. RC1 является предварительной сборкой. CI-шаблоны не активированы автоматически; нужны права GitHub на workflow и отдельное включение владельцем.

## 8. Обновление и полное удаление

Установленные версии проверяют стабильные GitHub Releases и скачивают обновления с подписанными метаданными в фоне. Остановка сессии, установка и перезапуск требуют подтверждения пользователя. Profile, Workspace, настройки и закреплённый IP сохраняются отдельно. Windows portable обновляется вручную полной заменой комплекта. Первый переход с версии без updater выполняется вручную.

Для удаления сначала штатно остановите сессию. Windows WFP BLOCK намеренно может пережить аварию; удаление EXE не является удалением остаточных политик. Универсального безопасного purge API WFP/AppContainer в текущей версии нет. Не отключайте Firewall и не удаляйте все сетевые правила.

Если отдельно включалась блокировка оригинального Claude, снимайте именно её комплектным `Block-OriginalClaude.ps1 -Mode Remove` с административными правами до удаления приложения. Скрипту нужен соответствующий установленный пакет Claude; после его удаления/замены восстановление может потребовать отдельной диагностики.

Windows также может иметь собственные HKCU-регистрации Guard: `Software\GateClaudeGuard`, `Software\Classes\GateClaudeGuard.Url.claude` и значение `Claude Proxy Guard` в `Software\RegisteredApplications`. Удаляйте только подтверждённые собственные записи, с проверкой метки и пути EXE; `UserChoice` напрямую не изменяйте. Portable не имеет автоматического de-register API.

После резервного копирования Workspace удалите файлы приложения, затем при необходимости пользовательские каталоги и собственные экспорты. Удаление профиля удаляет вход и локальные данные. На macOS завершите Guard через «Выйти», удалите `.app`, Application Support и настройки командой `defaults delete local.proxyguard.claude`. Постоянную службу, LaunchDaemon или Network Extension Guard не устанавливает.

Подробная [инструкция удаления и диагностики RC1](https://github.com/JFT-git/gate-claude/blob/4adfc43974ce5cf0a65392b581b94c8ac507a979/docs/operations.md).

## 9. Сообщение об уязвимостях

Используйте приватный канал GitHub Security, если он включён владельцем. Если приватного канала нет, публичный issue должен содержать только просьбу организовать контакт, без exploit, токенов и данных пользователя. Отдельные security email, PGP-ключ, bug bounty и гарантированный срок ответа не настроены.

Для разбора подготовьте версию/commit, платформу/архитектуру, безопасный синтетический пример, ожидаемый и фактический результат. Решение о внедрении требует оценки организацией описанных границ и недостающих проверок на её целевой платформе.
