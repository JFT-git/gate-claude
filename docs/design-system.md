# Дизайн-система и проверка интерфейса

## Основа

Дизайн проработан с Claude Code CLI, модель `claude-opus-5-5`: review опубликованных HTML/CSS baseline `6d5ede249b9992ae8222839fbd5b704d579275fb` и требований пользователя. CLI работал без инструментов, MCP, изменений файлов и доступа к профилю. Реализация и проверка рекомендаций выполнены в этом репозитории. Непубличные исходники, OAuth-коды, журналы и настройки в дизайн-запрос не передавались.

Стек сохранён: Electron HTML/CSS/JavaScript на Windows, SwiftUI на macOS. Растровые макеты, внешние шрифты и CDN не нужны. Windows использует локальный SVG sprite; macOS — SF Symbols. Иконки дополняют подписи, а не заменяют их.

## Компоненты и поведение

- Тёмные нейтральные поверхности, светлый текст, мятный акцент основного действия, отдельный цвет ошибки. Токены находятся в `Windows/src/ui/style.css`; macOS-кнопки — в `Source/DesignSystem.swift`.
- «Запустить», «Остановить», «Перезапустить» — одна горизонтальная группа одинаковой ширины и высоты. Windows: 46 px, macOS: 44 pt. При узком веб-viewport подпись остаётся, иконка переносится над ней внутри кнопки; сама группа не распадается.
- Основное действие зависит от подтверждённого состояния: запуск в idle, остановка при активности, перезапуск после блокировки. После IP-блокировки обычный запуск не разрешается. «Перезапустить» означает полный перезапуск Guard, с закрытием его сессии и повторным вводом пароля.
- Нажатие немедленно блокирует повтор той же операции. Пока подготовка запуска ещё не прислала событие состояния, остановка уже доступна. Во время незавершённого UAC перезапуск запрещён существующим контроллером и интерфейсом.
- Во время операции показаны текст этапа и индикатор. Результат и время последней операции доступны отдельно. Ошибка не исчезает сама; журнал открывается рядом с ней.
- Служба показывается отдельно от сессии Claude. В текущей сборке API отсутствует, кнопок установки нет. Шесть будущих состояний и действия принимаются только через контракт интеграции. Даже статус running будущего backend сам по себе не снимает per-session UAC.

## Доступность

Windows: семантические label/fieldset, видимый `:focus-visible`, ссылка пропуска к управлению, status/alert/live region, ARIA tabs и стрелки/Home/End, нативные disabled-кнопки, текстовое объяснение их доступности. Цвет не единственный носитель состояния. Поддерживаются reduced motion и forced colors; общий контент прокручивается при уменьшении окна и увеличении масштаба.

macOS: нативные контролы SwiftUI и названия кнопок, Return для запуска, Cmd+. для остановки, Cmd+L для журнала. Минимальное окно и ScrollView сохраняют доступ к настройкам. VoiceOver и высокий контраст требуют отдельной ручной проверки; наличие семантики не означает сертификацию доступности.

## Проверки

`node --test Windows/test/service-integration.test.cjs` проверяет контракт и отсутствие ложного успеха, readback состояния, блокировку дублей, безопасные ошибки и доступность управления.

`cd Windows && npx electron scripts/ui-smoke.cjs` запускает настоящий renderer с тестовым IPC и временным профилем: окно, равные кнопки, ошибку, повторные нажатия, остановку, состояния, клавиатурные вкладки и масштаб 200%. Сеть fixture запрещена. Скриншоты и JSON пишутся в `GATE_UI_TEST_OUT` либо временный каталог. Это проверка UI, не установленной службы, WFP или реального Claude.

Будущие состояния службы в этом harness — явно тестовые данные; в production backend отсутствует. Windows-native UAC/SCM, реальный Claude, VoiceOver/Narrator и Intel runtime этим тестом не проверяются.
