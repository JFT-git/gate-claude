# Эксплуатация, обновление и диагностика

## Установка и portable

Windows ZIP распаковывается целиком в локальную папку. Нельзя запускать EXE из архива или смешивать версии. Per-user NSIS устанавливает приложение в `%LOCALAPPDATA%\Programs\Claude Proxy Guard`, затем вызывает `resources\GuardService.exe --request-install` и ждёт установку auto-start службы `ClaudeProxyGuard`. Первый install требует один UAC. Ошибка службы, включая native exit 2, прерывает setup и не считается успешной установкой. Если совместимая служба уже running, повторный запрос возвращает `elevated:false`.

Portable содержит тот же requester. При первой защищённой сессии он тоже устанавливает службу с UAC; последующие сессии с неизменной running service не требуют повышения. Изменение `GuardService.exe` или `NetworkFence.exe` означает privileged update с новым UAC. Удаление службы требует отдельного elevation. Не запускайте Guard как администратор для обхода этой модели.

macOS `.app` можно перенести из ZIP/DMG в свою папку Applications или общую `/Applications`. Общая папка может требовать системное разрешение на копирование. Для работы приложения root не нужен. При обычном запуске Guard появляется только в меню-баре; окно открывается пунктом «Открыть Claude Proxy Guard». Закрытие окна возвращает приложение в меню-бар без остановки сессии, а «Выход» завершает её через штатный shutdown. Ad-hoc-сборка не имеет Developer ID/notarization; доверие к происхождению нужно оценивать самостоятельно по release и checksum.

Portable не означает «без следов» и не хранит профиль рядом с программой. Данные находятся в каталоге пользователя. На Windows AppContainer/WFP и на macOS локальная копия — разные механизмы, их границы нельзя объединять.

## Обычный день

1. Выберите текущую сеть/VPN или SOCKS5. VPN включается отдельно.
2. Нажмите «Запустить». Выполнение показывает реальные сообщения движка без выдуманных процентов.
3. На Windows при первом install/privileged update ответьте на UAC. Пока запрос не завершён, повторное повышение и перезапуск блокируются. Для current running service этого окна нет.
4. Состояние «Claude под защитой Guard» появляется по фактическому событию контроллера, а не по нажатию кнопки.
5. «Остановить» отправляет существующую команду остановки; во время запуска это отмена. «Перезапустить» завершает сессию и заново открывает Guard, не запуская Claude автоматически. Пароль прокси нужно ввести снова.

Временная ошибка проверки, сон или смена маршрута приостанавливают и трафик, и сам процесс Claude на 20 секунд. Возврат разрешённого IP размораживает его с тем же PID и профилем; открытые потоки при этом не восстанавливаются. Если адрес не вернулся, выполняется graceful close до 5 секунд и затем принудительное завершение. RU-маршрут, потеря WFP/PF и diagnostic/security failures сразу блокируют сессию без этого ожидания.

## Обновление

Установленное приложение проверяет стабильные GitHub Releases при запуске и раз в сутки, скачивает подписанное обновление в фоне и показывает прогресс. Кнопка ручной проверки не блокирует основную сессию. Перед установкой подтвердите остановку Claude и перезапуск Guard; дождитесь завершения shutdown, не выключайте компьютер во время установки. После перезапуска выберите маршрут и запустите Claude заново — сессия и прокси-пароль не наследуются.

Если service API и оба privileged binary не изменились byte-for-byte, обновление приложения не вызывает повторный service UAC. Изменение любого privileged binary требует одного update request с UAC. Stock `csc` без deterministic mode может изменить bytes при пересборке; такой binary считается изменённым. Не обещается бесплатное удаление или бесплатный privileged update.

Profile, CodeState, Workspace, настройки, diagnostics и `ip-memory.json` сохраняются. Windows portable не обновляется автоматически: остановите сессию, закройте Guard, сверьте SHA-256 и замените всю распакованную папку, не смешивая файлы разных версий. После переноса portable-папки проверьте обработчик ссылок Claude: регистрация содержит абсолютный путь.

Если подпись/хеш не совпал, пакет повреждён или установка прервана, не заменяйте файлы вручную внутри действующей установки. Используйте ручной Setup/ZIP/DMG из проверенного релиза как recovery. Первый переход с версии без updater выполняется один раз вручную.

## Где находятся данные

- Windows: `%APPDATA%\Claude Proxy Guard\Guard` — настройки, `diagnostics.json`, Profile, Cache/runtime и CodeState. Постоянная рабочая папка: `CodeState\Workspace`. Авторизация Claude/Code хранится в их собственных профилях; это чувствительные данные. Privileged binaries: `%ProgramData%\Claude Proxy Guard\Service`, изменение только SYSTEM/Administrators.
- macOS: `~/Library/Application Support/ClaudeProxyGuard` — Profile, Runtime и `Diagnostics/events.jsonl` до 80 событий. Настройки UserDefaults: домен `local.proxyguard.claude`.
- Пароль SOCKS5 не сохраняется настройками Guard. Хост, порт и логин могут сохраняться.
- Трафик находится в памяти до явного экспорта.

## Разбор ошибки

Откройте журнал из заголовка или баннера ошибки. Соберите версию/commit, Windows или macOS и архитектуру, действие, последний этап и фиксированный код ошибки. Не публикуйте Profile, Workspace, magic link, адреса, cookies, пароль и содержимое чата.

Если UAC не появился при первом install/update, проверьте «Журнал защиты» Windows и полноту пакета. Не отключайте Defender/Firewall и не меняйте права WindowsApps. `not_installed`, `stopped`, `update_required` и `error` означают, что session routing недоступен; production не откатывается на старый per-session helper. `resources\GuardService.exe --status` возвращает authoritative JSON. Start/stop доступны только узкими native requests; stop отклоняется при активных brokers.

Code закреплён на Desktop 1.44121.2 / CLI 2.1.304. Ошибка после автоматического обновления Claude требует проверки совместимости; кнопка повторного запуска не отменяет проверку исходных хешей.

## Полное удаление

**Сначала сохраните рабочие документы и нужные данные. Удаление профилей необратимо удалит вход и локальную историю.**

### Windows

1. Выполните штатную остановку в Guard, дождитесь завершения и закройте приложение. Если завершение сетевой защиты не подтверждено, сначала восстановите штатную остановку той же версией из той же папки: приватные WFP BLOCK намеренно переживают аварию.
2. Если вручную включалась блокировка **исходного** Claude, используйте комплектный `Block-OriginalClaude.ps1 -Mode Remove` из повышенного PowerShell до удаления файлов программы. Он удаляет только правила с собственными метками; script требует установленный соответствующий пакет Claude. Если пакет уже удалён/изменён, автоматическое полное восстановление этим сценарием не гарантируется — нужна отдельная диагностика владельца правил. Не удаляйте все правила WFP/Firewall.
3. Удалите службу штатным деинсталлятором. Он вызывает `GuardService.exe --request-uninstall`, требует elevation и прерывается при ошибке, включая exit 2. Для portable выполните из полного комплекта `resources\GuardService.exe --request-uninstall --owner 0` и проверьте `--status`. Простое удаление portable-папки службу не удаляет.
4. В Windows выберите нужное приложение для ссылок `claude`. Пользовательская регистрация Guard создаёт только HKCU `Software\GateClaudeGuard`, `Software\Classes\GateClaudeGuard.Url.claude` и значение `Claude Proxy Guard` в `HKCU\Software\RegisteredApplications`. Рецепт установщика удаляет эти данные только при совпадении собственной метки и пути установленного EXE; portable-версия автоматического de-register API не имеет. Проверку/удаление именно этих собственных записей выполняет владелец профиля вручную. `UserChoice` и универсальный класс `claude` напрямую не изменяйте.
5. Удалите папку приложения. Service request проверяет точный owned ImagePath и удаляет только `GuardService.exe`, `NetworkFence.exe` и пустые собственные каталоги. Чужие службы, неизвестные файлы и ACL не затрагиваются. Профиль, документы и сетевые правила не считаются автоматически очищенными.
6. Для очистки пользовательских данных отдельно удалите `%APPDATA%\Claude Proxy Guard` после резервного копирования Workspace. Удалите свои экспорты из выбранных каталогов.

Не используйте универсальный `sc delete`, очистку всего ProgramData или удаление всех WFP/AppContainer объектов как замену owned uninstall. При остаточных WFP/AppContainer объектах после аварии универсального безопасного purge API нет; не считайте удаление EXE полным удалением защиты.

### macOS

1. Остановите сессию, выберите «Выйти» из меню Guard. Закрытие только окна может оставить приложение в строке меню.
2. Удалите `.app` и ненужный DMG/ZIP.
3. По желанию удалите `~/Library/Application Support/ClaudeProxyGuard` и свои экспорты.
4. Для настроек текущего пользователя: `defaults delete local.proxyguard.claude`. Отсутствующий домен не является ошибкой удаления программы.

LaunchDaemon, LaunchAgent, Network Extension или постоянную службу Guard не устанавливает. Оригинальный Claude и его отдельные пользовательские данные не удаляются.
