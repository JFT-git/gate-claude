# Эксплуатация, обновление и диагностика

## Установка и portable

Windows ZIP распаковывается целиком в локальную папку. Нельзя запускать EXE из архива или смешивать версии. Для приложения достаточно обычного пользователя; новая защищённая сессия отдельно требует UAC NetworkFence. Рецепт Inno Setup устанавливает приложение в `%LOCALAPPDATA%\Programs\Claude Proxy Guard` для текущего пользователя. Это не установщик службы.

macOS `.app` можно перенести из ZIP/DMG в свою папку Applications или общую `/Applications`. Общая папка может требовать системное разрешение на копирование. Для работы приложения root не нужен. Ad-hoc-сборка не имеет Developer ID/notarization; доверие к происхождению нужно оценивать самостоятельно по release и checksum.

Portable не означает «без следов» и не хранит профиль рядом с программой. Данные находятся в каталоге пользователя. На Windows AppContainer/WFP и на macOS локальная копия — разные механизмы, их границы нельзя объединять.

## Обычный день

1. Выберите текущую сеть/VPN или SOCKS5. VPN включается отдельно.
2. Нажмите «Запустить». Выполнение показывает реальные сообщения движка без выдуманных процентов.
3. На Windows ответьте на UAC. Пока запрос не завершён, повторное повышение и перезапуск блокируются.
4. Состояние «Claude под защитой Guard» появляется по фактическому событию контроллера, а не по нажатию кнопки.
5. «Остановить» отправляет существующую команду остановки; во время запуска это отмена. «Перезапустить» завершает сессию и заново открывает Guard, не запускает Claude автоматически. Пароль прокси нужно ввести снова.

Подтверждённый другой IP закрывает сессию до перезапуска. Временная ошибка проверки, сон или смена маршрута приостанавливают трафик; подтверждённый прежний IP позволяет продолжить. Между проверками остаётся интервал.

## Обновление

Сначала остановите сессию и закройте Guard. Сверьте платформу/архитектуру и SHA-256 нового артефакта. Замените всю папку приложения или весь `.app`, сохранив пользовательские каталоги. Автообновления Guard нет. После переноса Windows portable-папки снова проверьте обработчик ссылок Claude в параметрах Windows: регистрация содержит абсолютный путь.

## Где находятся данные

- Windows: `%APPDATA%\Claude Proxy Guard\Guard` — настройки, `diagnostics.json`, Profile, Cache/runtime и CodeState. Постоянная рабочая папка: `CodeState\Workspace`. Авторизация Claude/Code хранится в их пользовательских профилях; это чувствительные данные.
- macOS: `~/Library/Application Support/ClaudeProxyGuard` — Profile, Runtime и `Diagnostics/events.jsonl`. Настройки UserDefaults: домен `local.proxyguard.claude`.
- Пароль SOCKS5 не сохраняется настройками Guard. Хост, порт и логин могут сохраняться.
- Трафик находится в памяти до явного экспорта. Экспорт хранится там, где выбрал пользователь, и не удаляется автоматически.

## Разбор ошибки

Откройте журнал из заголовка или баннера ошибки. Соберите версию/commit, Windows или macOS и архитектуру, действие, последний этап и фиксированный код ошибки. Не публикуйте Profile, Workspace, magic link, адреса, cookies, пароль и содержимое чата.

Если UAC не появился, проверьте «Журнал защиты» Windows и полноту распакованного пакета. Не отключайте Defender/Firewall и не меняйте права WindowsApps. Если ответ API службы недоступен, это ожидаемое отсутствие интеграции; текущий брокер не становится постоянной службой после установки приложения.

Code закреплён на Desktop 3.1623.0 / CLI 2.1.304. Ошибка после автоматического обновления Claude требует проверки совместимости; кнопка повторного запуска не отменяет проверку исходных хешей.

## Полное удаление

**Сначала сохраните рабочие документы и нужные данные. Удаление профилей необратимо удалит вход и локальную историю.**

### Windows

1. Выполните штатную остановку в Guard, дождитесь завершения и закройте приложение. Если завершение сетевой защиты не подтверждено, сначала восстановите штатную остановку той же версией из той же папки: приватные WFP BLOCK намеренно переживают аварию.
2. Если вручную включалась блокировка **исходного** Claude, используйте комплектный `Block-OriginalClaude.ps1 -Mode Remove` из повышенного PowerShell до удаления файлов программы. Он удаляет только правила с собственными метками; script требует установленный соответствующий пакет Claude. Если пакет уже удалён/изменён, автоматическое полное восстановление этим сценарием не гарантируется — нужна отдельная диагностика владельца правил. Не удаляйте все правила WFP/Firewall.
3. В Windows выберите нужное приложение для ссылок `claude`. Пользовательская регистрация Guard создаёт только HKCU `Software\GateClaudeGuard`, `Software\Classes\GateClaudeGuard.Url.claude` и значение `Claude Proxy Guard` в `Software\RegisteredApplications`. Рецепт установщика удаляет эти данные только при совпадении собственной метки и пути установленного EXE; переносимая версия автоматического de-register API не имеет. Проверку/удаление именно этих собственных записей при portable-деинсталляции выполняет администратор/владелец профиля вручную. `UserChoice` и универсальный класс `claude` напрямую не изменяйте.
4. Удалите папку приложения или запустите её пользовательский деинсталлятор. Деинсталлятор не удаляет профиль, документы, сетевые правила и чужие программы.
5. Для очистки пользовательских данных отдельно удалите `%APPDATA%\Claude Proxy Guard` после резервного копирования Workspace. Удалите свои экспорты из выбранных каталогов.

Постоянная служба этой версией не создаётся, команды `sc delete` для неё нет. Если администратор добавил собственную службу вне проекта, её удаление должно выполняться средствами её поставщика. При остаточных WFP/AppContainer объектах после аварии универсального безопасного purge API в этой версии нет; не считать удаление EXE полным удалением защиты. Это явное ограничение продукта.

### macOS

1. Остановите сессию, выберите «Выйти» из меню Guard. Закрытие только окна может оставить приложение в строке меню.
2. Удалите `.app` и ненужный DMG/ZIP.
3. После резервного копирования удалите `~/Library/Application Support/ClaudeProxyGuard` и свои экспорты.
4. Для настроек текущего пользователя: `defaults delete local.proxyguard.claude`. Отсутствующий домен не является ошибкой удаления программы.

LaunchDaemon, LaunchAgent, Network Extension или постоянную службу Guard не устанавливает. Оригинальный Claude и его отдельные пользовательские данные не удаляются.
