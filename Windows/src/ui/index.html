Что контролирует Guard

Guard направляет Chromium через свой локальный шлюз: далее через текущую сеть / VPN или выбранный SOCKS5. Проверяется страна выходного IP; наличие конкретного VPN-клиента не требуется и само по себе не подтверждает иностранный IP. Перехватываются доступные HTTP, SSE и WebSocket. Guard закрывает шлюз и дерево процессов через Windows Job Object. Перед запуском Windows запрашивает UAC для сетевого брокера. WFP ограничивает существующие EXE частной копии единственным TCP-портом Guard на 127.0.0.1; прямые UDP и IPv6 запрещены. Claude запускается с обычными правами. В runtime запрещены прямые Node-соединения, внешние процессы и приложения; MCP, Cowork, native-модули и некоторые способы входа могут быть недоступны. Это ограничение по путям EXE, а не контейнер всего дерева: новые EXE и обращения через системные службы требуют отдельной ОС-изоляции.

Проверки ipwho.is, ipify и служебных адресов claude.ai / api.anthropic.com получают выходной IP без данных чата. Публичный IP за NAT или прокси нельзя определить локально. Между проверками внешнего IP остаётся интервал; смену адреса на удалённом NAT невозможно узнать мгновенно. При сбое проверки трафик закрыт до подтверждения прежнего IP. Трафик хранится в памяти; известные токены скрываются, но произвольные поля могут содержать секреты. Перед экспортом проверьте содержимое.

Claude находится по сведениям установленных MSIX-пакетов, без открытия WindowsApps вручную и без изменения её прав доступа. Для локальной копии обновляется целостность ASAR; исходная цифровая подпись к ней не применяется. Файлы Claude не включены в сборку. Приложение независимо от Anthropic.
