# Claude Proxy Guard для Windows · 0.4.1

Переносимая сборка x64 для Windows 10/11. Внутри — собственный Guard, Electron и небольшой helper Windows Job Object. Файлы Claude, учётные записи, пароли и тестовые сертификаты не распространяются. Проверено на Windows 11 x64 и официальном Claude Desktop 3.1623.0.

## Запуск

1. Полностью распакуйте `ClaudeProxyGuard-Windows-x64-0.4.1.zip`. Запускайте `Claude Proxy Guard.exe` из распакованной папки; рядом нужны остальные файлы.
2. Guard автоматически найдёт Claude в установленных пакетах Windows, включая скрытую `Program Files\WindowsApps`. Путь берётся из реестра пакетов и их манифеста; вручную открывать папку и менять её права не требуется. Кнопка **Найти** повторяет поиск. Автоматический режим заново проверяет установку перед каждым запуском, поэтому обновление Claude и прежний сохранённый путь не мешают поиску. Для нестандартной установки есть **EXE…**. Скачать Claude можно на [официальном сайте](https://claude.com/download).
3. Выберите **Текущая сеть / VPN**, чтобы использовать уже включённый VPN или обычный маршрут Windows без SOCKS5. Проверяется именно выходной IP и его страна: отдельное распознавание VPN-клиента не нужно. Либо выберите **SOCKS5-прокси** и введите свой хост, порт и, при необходимости, логин/пароль. `127.0.0.1:1080` требует работающего локального SOCKS5. Guard не включает VPN и не предоставляет прокси.
4. Оставьте `Europe/Amsterdam`, `en-US`, выберите интервал и нажмите **Проверить и запустить**. Оба сервиса проверки IP должны показать один адрес; RU и неизвестная страна блокируются.
5. При первом запуске создаётся отдельная локальная копия Claude. Нужны свободное место под неё и время на копирование. Вход в Claude выполняется в новом профиле; прежние cookies, переписка, токены и настройки не переносятся.
6. Для перехвата содержимого включите **Показывать тела запросов и ответов** до запуска. Выберите запись в разделе **Трафик**. Доступны HTTP, SSE и текстовые WebSocket-сообщения Chromium.
7. После защитной блокировки или ручного завершения сессии нажмите **Перезапустить Guard**. Пароль SOCKS5 нужно ввести снова. Закрытие окна завершает Guard и его копию Claude.

## Как закрывается соединение

Случайный порт HTTP CONNECT доступен только на `127.0.0.1`. До начальной проверки разрешены только IP-сервисы. В режиме **Текущая сеть / VPN** назначения открываются через действующую сеть Windows; DNS также следует настройкам Windows/VPN. В режиме **SOCKS5** назначения и их DNS передаются указанному SOCKS5-серверу; на прямое подключение при его отказе Guard не переходит. Эти режимы выбираются явно. Отказ одного назначения и сброс отдельного TCP-потока закрывают только этот запрос. Неверная авторизация, потеря прокси и ошибки контрольных IP-запросов блокируют всю сессию.

В обоих режимах в начале используются `ipwho.is` и `api64.ipify.org`; затем ipify проверяется каждые 2/5/10/30 секунд. RU, неизвестная страна и ошибка проверки не открывают доступ. Подтверждённый IP и страна видны в окне. Любой новый IP, включая другой иностранный, закрывает все туннели и дерево Claude до перезапуска Guard. Ошибка проверки, смена интерфейсов/локальных адресов/маршрута, сон или пробуждение также блокируют сессию. Учитываются обычные default routes и пары `/1`, используемые VPN. Интервалы считаются по монотонным часам, без накопления длительности запросов. При интервале 5 секунд обнаружение смены публичного IP может занять примерно 9 секунд. Публичный IP за NAT или прокси нельзя определить только локальными данными. Эти сервисы получают выходной IP, а не запросы Claude. «Не RU» не подтверждает поддержку страны сервисом Claude.

Claude создаётся приостановленным и включается в Windows Job Object до продолжения. Job Object имеет `KILL_ON_JOB_CLOSE`: закрытие stdin, авария helper или завершение Guard закрывают всё принадлежащее ему дерево. Guard отправляет heartbeat каждую секунду; отсутствие heartbeat дольше 5 секунд также закрывает дерево. Ручная остановка не снимает закрепление IP в текущем процессе Guard.

## Профиль и локальная копия

Каталог Guard: `%APPDATA%\Claude Proxy Guard\Guard`. В нём находятся `Runtime-…` с собственной копией, `Profile` с отдельным профилем, несекретные `settings.json` и ограниченный `diagnostics.json`.

Автопоиск сначала проверяет MSIX/Appx-пакеты текущего пользователя и `Application.Executable` их манифестов, затем App Paths и обычные каталоги установки. Проверяется чтение самого EXE и `resources/app.asar`; выбирается последняя доступная версия. Недоступный или удалённый файл не выдаётся за найденный. Владение и ACL WindowsApps не меняются. Ручной путь сохраняется только после явного выбора **EXE…**.

Guard добавляет свой bootstrap в локальную копию ASAR и пересчитывает существующий PE-ресурс `INTEGRITY/ELECTRONASAR`. Проверка целостности ASAR и защитные флаги Electron остаются включены. У изменённой копии снимается недействительная Authenticode-запись; она не выдаётся за подписанный Anthropic файл. Исходный EXE и его подпись не изменяются. Копия не обновляет себя; после обновления установленного Claude создаётся новая копия.

Обмен диагностикой идёт через Windows named pipe со случайным именем и одноразовым 256-битным токеном. Отладочный TCP-порт не открывается. Язык, locale и timezone применяются к доступным страницам/iframe через Electron debugger и CDP. Фактически проверяются `Intl.DateTimeFormat().resolvedOptions()`, `navigator.language` и язык запросов. Конфликт общей ICU-локали допускается только при подтверждённой правильной локали. Другой или неподтверждённый профиль закрывает сессию.

Системные настройки Windows не меняются. Переменные `TZ`/`LANG` передаются процессу, но это не заменяет все Win32 API, workers, VM, сохранённые данные аккаунта и серверные сведения.

## Данные

Пароль прокси остаётся в памяти Guard и не передаётся Claude. Настройки подключения сохраняются без пароля. Журнал до 80 служебных событий скрывает IP и не получает тела запросов. Трафик хранится в памяти: 200 записей, до 32 768 символов каждого направления. Известные Cookie/Authorization/токены и секретные JSON-поля маскируются, query и fragment URL удаляются. Это не универсальный поиск секретов; переписка и произвольные поля могут быть чувствительными. Запись трафика на диск выполняется только кнопкой **Экспорт JSON**.

Рабочая сборка не устанавливает сертификаты, не меняет системное доверие TLS и не содержит тестовой подмены IP. Она не читает пароли SSH, учётную запись Windows или старые данные Claude.

## Проверки и ограничения

`npm test` проверяет оба режима подключения, SOCKS5 с авторизацией, запрет до проверки, отсутствие прямого fallback, отказ отдельного назначения, закрытие живого туннеля при смене IP, закрепление до перезапуска, RU/ошибку сервиса, отмену запуска, поиск пакета/манифеста, выбор свежей версии, недоступные пути, локаль, named pipe и маскирование. На Windows также проверяется завершение дочернего и внучатого процессов при EOF, аварии helper и отсутствии heartbeat. `build.ps1` отдельно запускает собранный интерфейс.

Сквозной тест находится в `test/installed-e2e.cjs`. Параметры `--claude auto --network` проверяют автопоиск настоящей WindowsApps-установки и режим текущей сети. Используются новый профиль, локальный HTTPS-стенд и только тестовые IP-провайдеры. Временные Windows Firewall правила запрещают внешнюю сеть только EXE его тестовой копии и удаляются в `finally`; системное доверие сертификатам не меняется. Проверяются реальные Intl/язык, заголовок Accept-Language, POST/ответ, iframe, вспомогательные окна, общий locale renderer, WebSocket и разрыв SSE/процессов при синтетической смене IP. Физический WAN-IP, настоящий Cloudflare, вход в аккаунт, внешние прокси и переписка с Anthropic этим стендом не проверяются.

Guard управляет своим шлюзом и деревом процессов; рабочая версия не устанавливает системный firewall или VPN. Native/Node-запросы, внешние браузеры, MCP/CLI, Cowork и другие независимые компоненты могут использовать другие маршруты и быть не видны в перехвате. Отдельно запущенный оригинальный Claude не контролируется. Функции, требующие MSIX-идентичности, исходной подписи или сервисов Cowork, могут быть недоступны в частной копии.

Приложение независимо от Anthropic. Сборка не подписана вашим сертификатом издателя; Windows может показать предупреждение о неизвестном издателе. Поддержка ARM64 в этот x64-релиз не заявлена.

## Сборка

На Windows x64 нужны Node.js 22.12+ и штатный .NET Framework 4.x compiler (`csc.exe`). Для обычного запуска Node.js и SDK не нужны.

```powershell
cd Windows
.\build.ps1
```

Скрипт выполняет `npm ci`, упаковку Electron с компиляцией `native/GuardHost.cs`, тесты, проверку упакованного окна и создаёт ZIP с SHA-256 в `dist`. Версии npm-инструментов и Electron зафиксированы в `package-lock.json`. `npm start` для разработки требует подготовленных `resources/RuntimeBootstrap.cjs` и `resources/GuardHost.exe`; готовая сборка содержит их автоматически.

Для cross-build на macOS можно передать helper, предварительно собранный из этого исходника на Windows:

```sh
npm ci
node scripts/package.cjs --platform win32 --arch x64 --host /absolute/path/to/GuardHost.exe
```

Официальные описания: [Electron debugger](https://www.electronjs.org/docs/latest/api/debugger), [ASAR integrity для Windows](https://www.electronjs.org/docs/latest/tutorial/asar-integrity), [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [Node named pipes](https://nodejs.org/api/net.html#ipc-support).
