# Claude Proxy Guard для Windows · 0.9.5

Независимое приложение для Windows 10/11 x64. Требует отдельно установленного Claude Desktop. Для Claude Code поддерживаются Desktop 1.44121.2 и Store 4.23118.0; текущий закреплённый CLI — 2.1.317. ARM64, Git Bash и Git SSH не заявлены.

Запустите `ClaudeProxyGuard-Windows-0.9.5-x64-Setup.exe` для установки текущему пользователю или полностью распакуйте portable ZIP и запустите `Claude Proxy Guard.exe`. Нужна вся папка с Electron, native-помощниками и CodeTools. Установщик размещает эти же файлы в `%LOCALAPPDATA%\Programs\Claude Proxy Guard`.

В 0.9.0 добавлена постоянная служба с одним UAC на установку и обновлён нативный интерфейс. Обычные сессии и обновления с неизменными service binaries не требуют повторного повышения.

Выберите сеть/VPN или SOCKS5 и нажмите «Запустить». При первой установке `ClaudeProxyGuard` Windows один раз запросит повышение для защищённой службы; обычные последующие сессии с совместимой running service не требуют UAC. Дождитесь фактической проверки Claude. Guard ищет Claude в установленных пакетах WindowsApps; менять ACL WindowsApps не нужно. Code использует постоянную `Guard\CodeState\Workspace`, если проект не выбран. Рабочие файлы сохраняются после выхода.

Проверка внешнего IP идёт параллельно через ipwho.is, ipinfo.io и ipapi.co, повторная — через ipify, ipinfo.io и ipapi.co. Два согласованных ответа завершают её без ожидания остальных сервисов; один доступный сервис является явным fallback, противоречия блокируются. Карточка «Диагностика сети» показывает подтвердившие сервисы, ASN/оператора, задержки Claude, внешнюю DNS-метрику, фактические ограничения WebRTC/QUIC и профиль. Сторонняя метрика не определяет разрешение запуска. После закрепления IP hostname-запросы выполняются через Cloudflare/Google DoH по числовым адресам с привязкой к проверенному egress; отказ обоих провайдеров закрывает CONNECT без системного DNS или UDP fallback.

В меню **«Обновления»** доступны фоновая проверка, статус, установка после подтверждения и страница выпусков. Для проверки закрывать Guard не требуется; установка по-прежнему завершает Claude и перезапускает Guard после явного подтверждения.

NSIS вызывает `GuardService.exe --request-install` после копирования файлов и прерывает установку при неподтверждённом результате, включая exit 2. Изменение service/NetworkFence binary требует нового privileged update; удаление службы требует отдельного elevated request. Служба запускает только pinned NetworkFence из `%ProgramData%\Claude Proxy Guard\Service`, не Claude и не произвольные команды. Portable использует ту же первую установку службы и не отменяет UAC. Архитектура службы и ограничения описаны в [service integration](../docs/service-integration.md); standard-user install и Chat/Code проверены на Windows 11.

В 0.8.0 добавлена фактическая заморозка Claude на 20 секунд с продолжением при возврате разрешённого IP. При восстановлении сохраняются тот же PID и профиль; открытые потоки не восстанавливаются. После дедлайна выполняется graceful close до 5 секунд и принудительное завершение. Добавлены новый нативный UI, countdown и обновлённая история. Автообновление из GitHub Releases подписывается Ed25519, NSIS поддерживает дельта-загрузку с full-package fallback. Прежние сетевые ограничения и правила IP сохранены; мгновенное отсутствие всех возможных утечек не обещается.

«Перезапустить» заново открывает Guard, закрывает его сессию и требует повторного ввода пароля прокси. После блокировки используется именно полный перезапуск. При обновлении Guard дождитесь завершения shutdown и нового запуска; Claude автоматически не стартует. Профиль, CodeState и Workspace хранятся в `%APPDATA%\Claude Proxy Guard\Guard` и не удаляются автоматически. Перед удалением штатно остановите сессию и закройте Guard.

Журнал показывает этап и фиксированный код ошибки. Кнопка **«Собрать логи»** сохраняет ZIP с версиями, обезличенным состоянием сессии/службы и техническими событиями freeze/thaw. **«Папка логов»** открывает `%APPDATA%\Claude Proxy Guard\Guard\logs`. Журналы ограничены 512 КиБ плюс один предыдущий сегмент на файл; IP, proxy-host, email, пользовательские пути и известные секреты маскируются при записи. Profile, CodeState, settings, ip-memory и трафик в ZIP не включаются. Перед передачей архив всё равно следует просмотреть.

Экспорт трафика может содержать переписку и секреты: не публикуйте его без проверки. Пароль прокси хранится в памяти; профиль Claude содержит собственные токены и cookies.

Комплект содержит `Documentation` с README, сведениями для ИБ, диагностикой и полным удалением. Онлайн: [руководство](https://github.com/JFT-git/gate-claude/blob/main/README.md), [безопасность](https://github.com/JFT-git/gate-claude/blob/main/SECURITY.md), [релизы и реальные статусы проверок](https://github.com/JFT-git/gate-claude/releases).

Сборка не подписана Authenticode. Update metadata подписывается отдельным Ed25519-ключом; это не подпись издателя Windows. Сверяйте SHA-256 и исходный commit из релиза. Приложение не связано с Anthropic и не имеет заявленных сертификатов ИБ.

Постоянный IP сохраняется в `Guard/ip-memory.json` в каталоге данных приложения. Другой адрес, включая отдельный выход к Claude, не принимается после перезапуска. Сброс доступен только после остановки сессии и подтверждения предупреждения; отмена сохраняет закрепление. Повреждённая память и ошибка записи блокируют запуск.
