# Claude Proxy Guard для Windows · 0.6.0

Переносимая сборка x64 для Windows 10/11. Внутри — собственный Guard, Electron, helper Windows Job Object и брокер сетевых правил WFP. Копия Claude запускается обычным процессом Windows; Docker, Hyper-V и отдельная VM для этой сборки не нужны. Файлы Claude, учётные записи, пароли и тестовые сертификаты не распространяются. Проверено на Windows 11 x64 и официальном Claude Desktop 3.1623.0.

## Claude Code

Включите **Claude Code в изоляции Guard** перед запуском. Этот режим рассчитан на закреплённые версии Claude Desktop 3.1623.0 и native Claude Code 2.1.304; неизвестное обновление не запускает Code без проверки совместимости. При выключенном режиме нативные дочерние процессы остаются запрещены.

Режим использует AppContainer без сетевых capabilities и отдельный Job Object. Правила WFP привязаны к SID контейнера и действуют на дочерние Git и PowerShell. Разрешён только TCP к точному локальному порту Guard; остальные прямые TCP/UDP/IPv6 запрещены. Нативный CLI загружается с закреплённого официального HTTPS-адреса через Guard после проверки страны и IP, проверяется по размеру и SHA-256. Файлы Claude не включаются в пакет Guard.

Рабочие файлы сохраняются в `Guard\CodeState\Workspace` и его подпапках. Отдельные переносимые Git и PowerShell подготавливаются из проверенных ZIP; существующие проекты, WindowsApps и системные права не меняются. DNS назначения native Code передаётся прокси. Git HTTPS и PowerShell используют тот же шлюз; неподдерживаемые прямые подключения, включая прямой Git SSH, блокируются. После смены IP закрываются шлюз и процессы Code; неизвестный результат завершения сохраняет сетевой запрет. Обычный Chat сохраняет прежний механизм ограничений.

Code использует штатный Windows-инструмент PowerShell: `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`, `defaultShell: powershell`, `permissions.deny: ["Bash"]`. Git Bash несовместим с используемым AppContainer и не запускается как инструмент Code. Bash-скрипты и hooks автоматически не переводятся: для поддерживаемых hooks задайте `shell: "powershell"` либо прямой запуск программы. Права системного пространства объектов ради Bash не расширяются. [PowerShell в Claude Code](https://code.claude.com/docs/en/tools-reference#powershell-tool).

Для сборки с инструментами передайте `--code-tools-dir` — папку с двумя ZIP и `code-tools-policy.json`, созданную `scripts/prepare-code-tools.cjs` из официальных проверенных исходных архивов. Cross-build дополнительно требует `--code-host`, собранный из `native/CodeHost.cs`; сетевой брокер компилируется из `NetworkFence.cs`, `CodeNetworkFence.cs` и `CodeFenceSession.cs`.

Подготовщик инструментов принимает `--git-root`, `--powershell-root`, `--git-asset`, `--powershell-asset`, `--powershell-bootstrap` и `--output`. Bootstrap — отдельная папка с собранным `GuardPowerShell.exe` и исходными `Guard.PowerShell.pssc`/`Guard.PowerShell.ps1` из `native`. Политика фиксирует официальные архивы, полный исходный PowerShell, эти три файла и полный итоговый комплект. Неизвестная пересборка launcher требует обновления проверенных хешей в исходной политике; произвольный EXE не принимается.

Сетевой запрет Code привязан к SID AppContainer, поэтому наследуется дочерними процессами и переименованными EXE. Нативный CLI создаётся приостановленным, уже в двух Job Object: собственном и общем, которым владеет брокер. Перед возобновлением CodeHost получает одноразовое подтверждение текущей сессии Guard. Потеря брокера закрывает общий Job; незавершённая очистка оставляет запрет сети. Постоянные `CodeState` и `Workspace` при этом сохраняются.

Перехват тел в окне «Трафик» относится к Chromium. HTTPS нативного Code, Git и PowerShell проходит туннелем без расшифровки Guard; наличие туннеля не означает доступность его содержимого в журнале. Проверка страны и IP имеет описанную ниже задержку и не доказывает одинаковый выход прокси для каждого назначения.

## Запуск

1. Полностью распакуйте `ClaudeProxyGuard-Windows-x64-0.6.0.zip`. Запускайте `Claude Proxy Guard.exe` из распакованной папки; рядом нужны остальные файлы.
2. Guard автоматически найдёт Claude в установленных пакетах Windows, включая скрытую `Program Files\WindowsApps`. Путь берётся из реестра пакетов и их манифеста; вручную открывать папку и менять её права не требуется. Кнопка **Найти** повторяет поиск. Автоматический режим заново проверяет установку перед каждым запуском, поэтому обновление Claude и прежний сохранённый путь не мешают поиску. Для нестандартной установки есть **EXE…**. Скачать Claude можно на [официальном сайте](https://claude.com/download).
3. Выберите **Текущая сеть / VPN**, чтобы использовать уже включённый VPN или обычный маршрут Windows без SOCKS5. Проверяется именно выходной IP и его страна: отдельное распознавание VPN-клиента не нужно. Либо выберите **SOCKS5-прокси** и введите свой хост, порт и, при необходимости, логин/пароль. `127.0.0.1:1080` требует работающего локального SOCKS5. Guard не включает VPN и не предоставляет прокси.
4. Оставьте `Europe/Amsterdam`, `en-US`, выберите интервал и нажмите **Проверить и запустить**. Подтвердите запрос UAC для сетевого брокера; без подтверждённой установки правил Claude не запускается. Сам Claude работает с обычными правами пользователя. Оба сервиса проверки IP должны показать один адрес одного семейства; RU и неизвестная страна блокируются.
5. При первом запуске создаются отдельная локальная копия Claude и пустой профиль. Нужны свободное место под копию и время на подготовку. Вход выполняется отдельно: данные исходного профиля Claude не переносятся. Перед первой страницей Guard также дожидается сохранения собственного ключа шифрования Windows; это может занять несколько секунд. Последующие запуски используют тот же частный профиль.
6. Для перехвата содержимого включите **Показывать тела запросов и ответов** до запуска. Выберите запись в разделе **Трафик**. Доступны HTTP, SSE и текстовые WebSocket-сообщения Chromium.
7. После защитной блокировки или ручного завершения сессии нажмите **Перезапустить Guard**. Пароль SOCKS5 нужно ввести снова. Закрытие окна завершает Guard и его копию Claude.

## Вход по magic link

При обычном запуске Guard регистрирует для текущего пользователя собственный обработчик `claude://`, указывающий на `Claude Proxy Guard.exe`, и добавляет себя в список приложений Windows по умолчанию. Если Windows сохраняет привязку к AppX-версии исходного Claude, обычной записи URL Protocol недостаточно. Нажмите **Выбрать Guard для ссылок входа** и в открывшихся системных параметрах выберите **Claude Proxy Guard** для типа ссылок **CLAUDE**. Это штатный выбор Windows; Guard не переписывает защищённые UserChoice/hash и не меняет другие типы ссылок. Ссылку получает единственный процесс Guard и передаёт по аутентифицированному named pipe уже работающей защищённой копии Claude. Отдельная копия Claude вне Guard не запускается. Ссылка не записывается в журнал или настройки.

Перед открытием ссылки из письма запустите защищённую сессию кнопкой **Проверить и запустить**. Если сессия остановлена или заблокирована, ссылка отклоняется; она не запускает Claude и не восстанавливает сеть автоматически. При перемещении распакованной папки запустите Guard из нового места, чтобы обновить обработчик. Вход одноразовым кодом остаётся доступен.

## Как закрывается соединение

Случайный порт HTTP CONNECT доступен только на `127.0.0.1`. До начальной проверки и во время паузы IP-сервисы доступны только контрольным запросам Guard с отдельным случайным токеном; запросы Claude запрещены. В режиме **Текущая сеть / VPN** назначения открываются через действующую сеть Windows; DNS также следует настройкам Windows/VPN. В режиме **SOCKS5** назначения и их DNS передаются указанному SOCKS5-серверу; на прямое подключение при его отказе Guard не переходит. Эти режимы выбираются явно. Отказ одного назначения и сброс отдельного TCP-потока закрывают только этот запрос. Неверная авторизация закрывает сессию. Краткий транспортный обрыв SOCKS и ошибка контрольного IP-запроса приостанавливают трафик и запускают перепроверку без завершения Claude.

В обоих режимах в начале используются `ipwho.is` и отдельный IPv4/IPv6 endpoint ipify; затем ipify проверяется каждые 2/5/10/30 секунд. RU, неизвестная страна и ошибка проверки не открывают доступ. Подтверждённый IP и страна видны в окне. Любой подтверждённый новый IP, включая другой иностранный, закрывает все туннели и дерево Claude до перезапуска Guard. Временная ошибка проверки, смена интерфейсов/локальных адресов/маршрута, сон или пробуждение приостанавливают шлюз: существующие соединения закрываются, новые запросы приложения запрещены. Контрольные запросы требуют отдельного случайного токена, которого нет у Claude. Прежний подтверждённый IP возобновляет доступ того же процесса; при недостоверном ответе трафик остаётся закрытым, а проверка повторяется. Семейство ipify фиксируется по закреплённому IP (api.ipify.org для IPv4, api6.ipify.org для IPv6), чтобы смена IPv4/IPv6 сама по себе не считалась новым адресом. Учитываются обычные default routes и пары `/1`, используемые VPN. Таблица читается напрямую через `GetIpForwardTable2`, без запуска PowerShell и загрузки его сетевого модуля; ошибка чтения сохраняет закрытое состояние. Интервалы считаются по монотонным часам, без накопления длительности запросов. При интервале 5 секунд и четырёхсекундном тайм-ауте реакция может занять около 9 секунд; точное время зависит от планировщика и сети. До обнаружения удалённой смены NAT новое соединение может уже выйти с другого публичного IP. Проверка ipify также не подтверждает одинаковый выход для каждого сайта при раздельных маршрутах или прокси с несколькими выходами. Публичный IP за NAT или прокси нельзя определить только локальными данными. Эти сервисы получают выходной IP, а не запросы Claude. «Не RU» не подтверждает поддержку страны сервисом Claude.

GuardHost передаёт `PROC_THREAD_ATTRIBUTE_JOB_LIST` в `CreateProcess`: Claude создаётся приостановленным и уже включённым в собственный Windows Job Object. Перед `ResumeThread` helper проверяет членство процесса в этом Job. Ошибка или отсутствие поддержки такого запуска не приводят к обычному запуску без Job. `KILL_ON_JOB_CLOSE` завершает принадлежащее Job дерево при EOF stdin, аварии helper или завершении Guard. Guard отправляет heartbeat каждую секунду; отсутствие heartbeat дольше 5 секунд также закрывает дерево. Job управляет временем жизни процессов; сетевые ограничения WFP привязаны к конкретным путям EXE. Ручная остановка не снимает закрепление IP в текущем процессе Guard.

## Профиль и локальная копия

Каталог Guard: `%APPDATA%\Claude Proxy Guard\Guard`. В нём находятся `Runtime-…` с собственной копией, `Profile` с отдельным профилем, несекретные `settings.json` и ограниченный `diagnostics.json`.

`Profile` сохраняется между остановками, перезапусками Guard и пересозданием `Runtime-…` после обновления Claude или bootstrap. Guard использует его повторно в том же каталоге данных Windows-пользователя; cookies, localStorage и другие данные, которые сохраняет сам Claude, не удаляются при штатной остановке. Очистка или удаление `Profile` создаст новый пустой профиль. Это не перенос учётной записи из оригинального Claude.

Автопоиск сначала проверяет MSIX/Appx-пакеты текущего пользователя и `Application.Executable` их манифестов, затем App Paths и обычные каталоги установки. Проверяется чтение самого EXE и `resources/app.asar`; выбирается последняя доступная версия. Недоступный или удалённый файл не выдаётся за найденный. Владение и ACL WindowsApps не меняются. Ручной путь сохраняется только после явного выбора **EXE…**.

Guard добавляет свой bootstrap в локальную копию ASAR и пересчитывает существующий PE-ресурс `INTEGRITY/ELECTRONASAR`. Проверка целостности ASAR и защитные флаги Electron остаются включены. У изменённой копии снимается недействительная Authenticode-запись; она не выдаётся за подписанный Anthropic файл. Исходный EXE и его подпись не изменяются. Копия не обновляет себя; после обновления установленного Claude создаётся новая копия.

Обмен диагностикой идёт через Windows named pipe со случайным именем и одноразовым 256-битным токеном. Отладочный TCP-порт не открывается. Язык, locale и timezone применяются к доступным страницам/iframe через Electron debugger и CDP. Фактически проверяются `Intl.DateTimeFormat().resolvedOptions()`, `navigator.language` и язык запросов. Конфликт общей ICU-локали допускается только при подтверждённой правильной локали. Другой или неподтверждённый профиль закрывает сессию.

Проверка исходящего языка применяется к настоящему HTTP-заголовку `Accept-Language`, а не к произвольным полям JSON. Русский текст, язык ответа, `account.language`, `locale` в данных и цитаты с названием часового пояса не завершают сессию. Они не доказывают системную локаль. Фактические `Intl`, `navigator.language` и timezone каждого активного контекста по-прежнему проверяются строго. Тела запросов не переписываются.

Системные язык, часовой пояс и общий прокси Windows не меняются. WFP-правила для частной копии устанавливаются отдельно через UAC. Переменные `TZ`/`LANG` передаются процессу, но это не заменяет все Win32 API, workers, VM, сохранённые данные аккаунта и серверные сведения.

## Данные

Пароль прокси остаётся в памяти Guard и не передаётся Claude. Настройки подключения сохраняются без пароля. Журнал до 80 служебных событий скрывает IP и не получает тела запросов. Трафик хранится в памяти: 200 записей, до 32 768 символов каждого направления. Известные Cookie/Authorization/токены и секретные JSON-поля маскируются, query и fragment URL удаляются. Это не универсальный поиск секретов; переписка и произвольные поля могут быть чувствительными. Запись трафика на диск выполняется только кнопкой **Экспорт JSON**.

Путь профиля передаётся Chromium ещё при создании процесса, а sessionData закрепляется за той же папкой. На Windows перед навигацией проверяется сохранение DPAPI-обёрнутого ключа в собственном `Local State`: иначе быстрый первый килл-свитч мог оставить зашифрованные cookies без сохранённого ключа. При ошибке или тайм-ауте страницы не открываются; данные не удаляются, шифрование не отключается. Остановка при смене IP не ждёт сохранения профиля.

Рабочая сборка не устанавливает сертификаты, не меняет системное доверие TLS и не содержит тестовой подмены IP. Она не читает пароли SSH, учётную запись Windows или старые данные Claude.

## Проверки и ограничения

`npm test` проверяет оба режима подключения, SOCKS5 с авторизацией, запрет до проверки, отсутствие прямого fallback, отказ отдельного назначения, закрытие живого туннеля при смене IP, закрепление до перезапуска, RU/ошибку сервиса, отмену запуска, поиск пакета/манифеста, выбор свежей версии, недоступные пути, локаль, named pipe и маскирование. На Windows также проверяются завершение дочернего и внучатого процессов при EOF, аварии helper, гибели родителя и отсутствии heartbeat, а также принудительное завершение helper во время создания процесса: приостановленный дочерний процесс не должен оставаться вне Job. `build.ps1` отдельно запускает собранный интерфейс. Для реальных WFP-проверок задайте GATE_FENCE_HELPER на собранный NetworkFence.exe; тест использует только специально созданную копию Node и локальные TCP/UDP/IPv6-серверы.

Сквозной тест находится в `test/installed-e2e.cjs`. Параметры `--claude auto --network` проверяют автопоиск настоящей WindowsApps-установки и режим текущей сети. Используются новый профиль, локальный HTTPS-стенд и только тестовые IP-провайдеры. Используется настоящий production WFP, дополнительные тестовые firewall-правила отсутствуют; системное доверие сертификатам не меняется. Ответ HTTP 500 проверяет паузу, отсутствие трафика Claude и восстановление прежнего PID при том же IP. Проверяются реальные Intl/язык, заголовок Accept-Language, POST/ответ, iframe, вспомогательные окна, общий locale renderer, WebSocket и разрыв SSE/процессов при синтетической смене IP. После остановки и нового запуска Guard стенд также проверяет сохранение тестовых постоянных HttpOnly cookies, localStorage и IndexedDB в том же `Profile`. Физический WAN-IP, настоящий Cloudflare, вход в аккаунт, внешние прокси и переписка с Anthropic этим стендом не проверяются.

Перед Claude запускается отдельный повышенный брокер NetworkFence.exe: Windows покажет UAC. Сам Claude остаётся обычным процессом пользователя. WFP устанавливает постоянные BLOCK для всех существующих EXE частной копии, разрешая только TCP на точный 127.0.0.1:порт Guard; прямые TCP на другие адреса/порты, UDP, IPv6 и входящие соединения запрещены. При аварии брокера ограничения сохраняются. Удаление возможно после завершения Job и независимой проверки отсутствия процессов этих EXE; следующая сессия атомарно обновляет собственные правила для той же копии. Системный mutex сериализует установку и удаление между брокерами; остановка во время установки требует перезапуска Guard и не открывает новую сессию поверх незавершённой. Правила принадлежат Administrators/SYSTEM. Прямые Node TCP/TLS/HTTP/DNS, workers, child_process, внешние приложения и загрузка native-модулей дополнительно запрещены bootstrap; QUIC отключён, WebRTC запрещает непроксируемый UDP, DNS Chromium направляется через relay. В режиме Chat это может отключать MCP/CLI, Cowork, native-функции и внешние способы авторизации. Режим Code разрешает только закреплённый CLI через отдельный CodeHost и AppContainer; общий запрет произвольного запуска из Electron сохраняется.

В режиме Chat WFP охватывает пути EXE, найденных в частной копии перед запуском. EXE по новому или внешнему пути не получает сетевые правила только потому, что его процесс попал в тот же Job Object. Native-вызов системного процесса, UNC/SMB и делегирование системным службам также требуют отдельной ОС-границы; bootstrap уменьшает доступные пути обхода, но не является контейнером для враждебного кода. Маршрут/DNS самого Guard в режиме текущей сети зависит от Windows/VPN; домен SOCKS-сервера разрешается ОС. Изменение публичного IP удалённого NAT между проверками нельзя исключить этой архитектурой. Поэтому отсутствие абсолютно всех утечек эта сборка не гарантирует. Для отдельно запущенного оригинального Claude предусмотрена отдельная постоянная блокировка ниже; она должна быть установлена администратором. Функции, требующие MSIX-идентичности, исходной подписи или сервисов Cowork, могут быть недоступны в частной копии.

Приложение независимо от Anthropic. Сборка не подписана вашим сертификатом издателя; Windows может показать предупреждение о неизвестном издателе. Поддержка ARM64 в этот x64-релиз не заявлена.

## Сборка

На Windows x64 нужны Node.js 22.12+ и штатный .NET Framework 4.x compiler (`csc.exe`). Для обычного запуска Node.js и SDK не нужны.

```powershell
cd Windows
.\build.ps1
```

Скрипт выполняет `npm ci`, упаковку Electron с компиляцией `native/GuardHost.cs` и `native/NetworkFence.cs`, тесты, проверку упакованного окна и создаёт ZIP с SHA-256 в `dist`. Версии npm-инструментов и Electron зафиксированы в `package-lock.json`. `npm start` для разработки требует подготовленных `resources/RuntimeBootstrap.cjs`, `resources/GuardHost.exe` и `resources/NetworkFence.exe`; готовая сборка содержит их автоматически.

Для cross-build на macOS можно передать helper, предварительно собранный из этого исходника на Windows:

```sh
npm ci
node scripts/package.cjs --platform win32 --arch x64 --host /absolute/path/to/GuardHost.exe --fence /absolute/path/to/NetworkFence.exe --code-host /absolute/path/to/CodeHost.exe --code-tools-dir /absolute/path/to/verified-sidecars
```

Официальные описания: [Electron debugger](https://www.electronjs.org/docs/latest/api/debugger), [ASAR integrity для Windows](https://www.electronjs.org/docs/latest/tutorial/asar-integrity), [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [Node named pipes](https://nodejs.org/api/net.html#ipc-support).


### Block the installed Claude outside Guard

On Windows, run `scripts/Block-OriginalClaude.ps1 -Mode Install` from an administrator PowerShell. Keep `native/OriginalClaudeFence.cs` in the repository layout, or put `OriginalClaudeFence.cs` beside the script when distributing it. This adds persistent inbound/outbound Block rules for the official `Claude_pzs8sxrjxfjjc` package family and every EXE in its currently installed WindowsApps package. It also installs persistent WFP image BLOCK filters for IPv4/IPv6 connect and accept, with no port, protocol or loopback exception. All firewall profiles must remain enabled. The package-family rule is independent of the versioned install path; run Install again after updates to refresh the additional EXE rules. The private Guard runtime and Guard relay are excluded from these program paths.

Use `-Mode Verify` to check effective rules, or `-Mode Remove` to remove only this script’s named and ownership-marked rules. Remove before uninstalling the source package so its executable inventory is available. The original Claude remains blocked when Guard is closed: launch protected sessions from Guard. This does not convert an independently launched original Claude into a proxied session or restrict arbitrary copies installed elsewhere. The original-image policy does not inherit to arbitrary external child executables. Guard's optional Claude Code mode uses a separate zero-capability AppContainer and package-SID network policy for the native CLI and its descendants. Windows administrators can change these rules.
