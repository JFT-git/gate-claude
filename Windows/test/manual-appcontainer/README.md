# Диагностика совместимости AppContainer

Ручной эксперимент для разработчика; в Guard и в сборку не включён. Это не работающий режим изоляции Claude.

В Windows 11 Pro build 26200 исходный подписанный Claude 3.1623.0.0 получил AppContainer-токен, Low integrity и нулевой список capabilities. После запуска он завершился с кодом `0x80000003` до первого пятисекундного снимка. Вход, HTTP/SSE и отсутствие утечек этим экспериментом не подтверждены. Повтор с файловым журналом дал тот же результат без созданного Chromium-журнала. Проверка отдельной неизменённой подписанной копии вне WindowsApps с разрешением RX только её временному SID также завершилась с тем же кодом. Причина завершения пока не установлена.

Для воспроизведения запустите обычный Windows PowerShell из этой папки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Compile-Probe.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-AppContainerProbe.ps1 -CaptureFatalLog
```

`ExecutionPolicy` задаётся только этому процессу. Тест находит Claude через MSIX-регистрацию, создаёт временный AppContainer и отдельный пустой профиль. Разрешения и Low integrity назначаются только новому scratch-каталогу. Права WindowsApps, основной профиль, firewall и loopback exemptions не меняются. Исходный Claude не исправляется и не перепаковывается. Сетевые capabilities отсутствуют, поэтому это тест запуска, а не тест работающего шлюза. Для осмысленного результата нужна действительная подпись исходного Claude.

На этой сборке Windows запрос token class 46 возвращает ошибку 87. Стенд явно отмечает проверку семантики LPAC через AccessCheck; это не прямой ответ API class 46. Основной токен проверяется до Resume, процесс назначается Job Object. Heartbeat/EOF завершает собственное дерево. Диагностика дочерних процессов ограничена этим Job.

JSON-вывод предназначен для локальной диагностики: он содержит случайные SID и PID. Не публикуйте его без отбора полей. Сборка и оригинальный профиль остаются вне теста; созданный scratch-каталог сохраняется для отдельной безопасной очистки. Не используйте этот исследовательский лаунчер как production-защиту: атомарное назначение Job при CreateProcess и watchdog, независимый от вывода, ещё требуют отдельной реализации.
