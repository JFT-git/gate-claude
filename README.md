# gate-claude

Независимый Claude Proxy Guard: **macOS 0.3.3** и **Windows x64 0.6.5**.

Готовые сборки: [GitHub Releases](https://github.com/JFT-git/gate-claude/releases). Исходники распространяются по MIT; Claude в комплект не входит.

Windows 0.6.0 добавляет режим Claude Code: native CLI и его дочерние процессы работают в AppContainer с сетевыми ограничениями по SID. Нативный Git HTTPS и PowerShell используют Guard; рабочая папка сохраняется в `Guard\CodeState\Workspace`. Code использует Windows-инструмент PowerShell; Git Bash и прямой Git SSH в этом режиме недоступны. Поддерживаются закреплённые Claude Desktop 3.1623.0 и Code 2.1.304. Подробности и границы защиты — в [инструкции Windows](Windows/README.md).

## Windows

В 0.6.5 ожидание ответа на системный запрос Windows отделено от установки сетевой защиты: окно UAC больше не истекает по таймеру Guard через две минуты. Повторный запрос не создаётся, пока предыдущий не завершён. Без подтверждённых правил Claude по-прежнему не запускается.

Подготовка прав существующего профиля теперь ожидает Windows до двух минут: большой профиль и инструменты Code больше не вызывают прежний 15-секундный тайм-аут. Набор разрешений сохранён; ошибка команды по-прежнему останавливает запуск.

В 0.6.4 повторная проверка после сетевой паузы подтверждает неизменность маршрута до и после запроса IP. Ответ, полученный на предыдущем маршруте, больше не может возобновить трафик на новом. Также устранён медленный разбор специально повреждённых HTTP-заголовков.

В 0.6.3 Claude Code автоматически использует постоянную защищённую папку `Guard\CodeState\Workspace`, если проект не выбран. Запрос из режима «Без папки» больше не уходит с домашним каталогом пользователя. Файлы сохраняются после выхода; доступ процессов Code ограничен AppContainer, а их сеть — Guard. Подробнее о защите папки — в [инструкции Windows](Windows/README.md#защищённая-рабочая-папка).

Распакуйте ZIP целиком и запустите `Claude Proxy Guard.exe`. Claude находится автоматически, включая MSIX-установку в скрытой WindowsApps; менять права папки не нужно. Выберите **Текущая сеть / VPN** для проверки выходного IP без SOCKS5 либо настройте **SOCKS5-прокси**, затем нажмите **Проверить и запустить**. RU и неизвестная страна запрещают запуск; подтверждённая смена закреплённого IP закрывает сессию. Временная ошибка проверки и сетевые уведомления приостанавливают трафик до подтверждения прежнего IP без завершения Claude. Нужны Windows 10/11 x64 и отдельно установленный Claude. Пароль прокси хранится только в памяти.

Windows-версия включает перехват HTTP/SSE/WebSocket, фактическую проверку `Europe/Amsterdam` / `en-US`, закрепление IP, кнопку перезапуска и Windows Job Object. Claude включается в Job атомарно при создании, до выполнения его кода; EOF, авария helper и отсутствие heartbeat дольше 5 секунд закрывают дерево. Копия запускается обычным процессом Windows, без Docker и отдельной VM. Системные язык, часовой пояс и общий прокси не меняются. Windows запрашивает UAC для WFP-ограничения существующих EXE частной копии единственным локальным портом Guard. Профиль копии сохраняется между запусками. WFP действует по путям этих EXE: новые внешние программы и обращения через системные службы не получают ограничения автоматически. Полные границы описаны в инструкции.

В Windows 0.5.2 ссылки `claude://` принимает Guard и передаёт работающей защищённой сессии. Если Windows выбирает AppX-версию исходного Claude, назначьте **Claude Proxy Guard** для ссылок **CLAUDE** через кнопку **Выбрать Guard для ссылок входа**. Произвольные поля языка в контенте больше не вызывают блокировку: проверяются фактический профиль браузера и исходящий `Accept-Language`.

Инструкция, ограничения и воспроизводимая сборка: [Windows/README.md](Windows/README.md). Код macOS находится в `Source`, код Windows — в `Windows/src`, общий bootstrap — в `Resources`.

## macOS

Независимое приложение для macOS 13+, Apple Silicon и Intel. Подключает установленный Claude Desktop к SOCKS5, проверяет внешний IP, задаёт `Europe/Amsterdam` и `en-US`, показывает доступные веб-запросы и ответы. Системные язык, часовой пояс и прокси macOS не меняются.

## Исправление 0.3.2: общая локаль renderer

В Chromium локаль ICU общая для процесса, а владение переопределением закреплено за CDP-агентом. Второй агент может получить `Another locale override is already in effect`, даже когда фактическая локаль уже правильная. Это поведение видно в [LocaleController Chromium](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/inspector/locale_controller.cc).

Guard обрабатывает отдельно только эту конкретную ошибку `Emulation.setLocaleOverride`. Далее обязательны фактические проверки `Intl.DateTimeFormat().resolvedOptions().locale`, таймзоны и `navigator.language` для каждого активного контекста. Другая локаль, неверный язык, отсутствие подтверждения и остальные ошибки команд останавливают сессию. Bootstrap также проверяет фактическую локаль до первой навигации. Чужое переопределение не сбрасывается.

Тест на настоящем Chromium установленного Claude создал несколько CDP-агентов одного renderer, воспроизвёл эту ошибку и подтвердил корректную работу bootstrap и Inspector с унаследованной `en-US`. Отдельно проверены отказ при неверной и неподтверждённой локали. Это дополняет тесты iframe, окон, HTTPS и kill switch версии 0.3.1.

## Исправления 0.3.1

- Закрытие вспомогательного окна вызывало `Debugger detached: target closed`, после чего адаптер сам завершал Claude. Обычное закрытие теперь очищает только соответствующую сессию. Неожиданная потеря диагностики живой страницы по-прежнему блокирует сессию. Событие [`detach`](https://www.electronjs.org/docs/latest/api/debugger#event-detach) возникает и при обычном закрытии WebContents.
- Ответы от уже закрытого iframe или уничтоженного контекста больше не завершают основную страницу. Повторное подключение одного target не запускает настройку дважды. Проверка профиля действующих страниц и iframe сохранена.
- Сброс одного установленного TCP-туннеля ошибочно считался отказом всего SOCKS5. Теперь закрывается этот туннель; остальные продолжают работать через тот же прокси. Неверная авторизация SOCKS5 закрывает сессию; транспортный сбой и потеря маршрута теперь приостанавливают трафик до перепроверки, а подтверждённый новый IP сохраняет блокировку до перезапуска.
- Чтение pipe и его закрытие выполняются последовательно на одной очереди, без гонки с `FileHandle.availableData`. Ожидающие команды получают ошибку при остановке.
- Добавлена кнопка **Перезапустить Guard** в окне и меню. Она закрывает Claude и шлюз и запускает новый процесс Guard. Пароль не переносится между процессами и потребуется снова, если прокси требует авторизацию.
- Причины блокировки и коды завершения сохраняются в ограниченном журнале. Исчезновение процесса больше не выдаётся за ручную остановку пользователя.

## Запуск

1. Откройте **Claude Proxy Guard.app**. Укажите установленный `/Applications/Claude.app` или выберите другой путь.
2. Выберите SOCKS5. Введите хост отдельно от порта, при необходимости логин и пароль. Приложение не предоставляет внешний прокси: `127.0.0.1:1080` работает только при уже запущенном локальном SOCKS5-сервере.
3. Оставьте `Europe/Amsterdam`, `en-US` или выберите другой профиль. Проверка страницы и перехват обязательны; показ тел можно отключить.
4. Нажмите **Проверить и запустить**. После проверки страны и IP Guard подготовит отдельную локальную копию Claude с адаптером. Первый запуск требует свободного места для копии приложения и занимает больше времени.
5. При первом запуске копии создаётся отдельный пустой профиль. Он используется повторно после остановки, перезапуска Guard и обновления локальной копии. Вход в Claude выполняется отдельно; данные исходного профиля не копируются. Откройте **Трафик**, чтобы увидеть доступные запросы и ответы.
6. После защитной блокировки нажмите **Перезапустить Guard** или завершите Guard через ⌘Q и откройте заново. Затем повторно введите пароль прокси, если он нужен, и нажмите **Проверить и запустить**. Ручная остановка и закрытие окна блокировку не снимают. Закрытие окна оставляет Guard в строке меню.

Альтернативный режим **Текущая сеть / VPN** использует текущий маршрут. VPN включается отдельно; Guard не меняет системную сеть и не создаёт VPN.

Пароль SOCKS5 хранится только в памяти. Несекретные настройки сохраняются. Журнал перехвата хранится в памяти; **Экспорт JSON** записывает его только по вашему нажатию. Сам Claude может сохранять данные в своём отдельном профиле. Остановка Guard принудительно завершает запущенную им копию; несохранённая работа может быть потеряна.

Кнопка **Журнал завершений** открывает расположение `~/Library/Application Support/ClaudeProxyGuard/Diagnostics/events.jsonl`. В нём до 80 служебных событий; права файла — 0600. Тела запросов, переписка и заголовки в этот журнал не передаются. Известные секреты, параметры URL и IP-адреса маскируются. Последняя сохранённая причина показывается и после нового запуска Guard.

## Локальная копия Claude

Оригинальный `Claude.app` не изменяется и не входит в комплект. Guard копирует установленное приложение в `~/Library/Application Support/ClaudeProxyGuard/Runtime-…/Claude.app`, добавляет собственный загрузчик, пересчитывает целостность ASAR и подписывает копию локальной ad-hoc подписью. Её профиль находится в `~/Library/Application Support/ClaudeProxyGuard/Profile`.

Обычные отладочные CLI-параметры установленный Claude 3.1623.0 отвергает. Адаптер использует Electron `webContents.debugger` и унаследованные pipe-дескрипторы 3/4. Диагностический TCP-порт не открывается. Подписанные Anthropic токены авторизации отладки не создаются и не подделываются.

Подпись исходника проверяется перед подготовкой. При неудаче интерфейс и журнал показывают предупреждение; успешная локальная подпись копии не подтверждает подлинность исходника. На этом Mac проверка исходного `/Applications/Claude.app` возвращает `invalid signature`; оригинал в ходе этой доработки не изменялся.

Guard не выдаёт Claude разрешения macOS и не восстанавливает сброшенные TCC-разрешения. Доступ к прежним элементам Связки ключей для переноса учётной записи не используется. Обычный вход в отдельном профиле и поведение самого Claude при нём этим тестом не проверены.

## Язык и часовой пояс

Для процесса задаются `TZ`, `LANG`, `LC_ALL`, `LC_MESSAGES`, `LANGUAGE`, `--lang`, `-AppleLanguages`, `-AppleLocale`. Наследующие окружение дочерние процессы получают те же параметры.

Для доступных страниц и iframe адаптер применяет `Emulation.setTimezoneOverride`, `Emulation.setLocaleOverride`, язык navigator и `Accept-Language` до навигации. Guard проверяет фактические `Intl.DateTimeFormat().resolvedOptions().timeZone`, `.locale` и `navigator.language`. Ошибка настройки, несовпадение или отсутствие подтверждения за 25 секунд останавливают копию.

Это не гарантирует замену всех нативных API, worker-контекстов, виртуальных машин, уже сохранённых настроек аккаунта или серверных данных. Содержимое переписки автоматически не переписывается.

## IP и блокировка

В начале HTTPS-запрос к `ipwho.is` проверяет IP и страну. RU, неизвестная страна и ошибка не открывают доступ. «Не RU» не означает, что страна поддерживается Claude. Затем адрес сверяется через `api.ipify.org` для IPv4 или `api6.ipify.org` для IPv6; сравниваются адреса одного семейства.

Адрес закрепляется за сессией. Подтверждённый другой IP, включая другой иностранный, закрывает шлюз, разрывает его действующие туннели, завершает запущенную копию Claude и блокирует запуск до перезапуска Guard. Временная ошибка проверки, смена локальных адресов или маршрута, сон, пробуждение и транспортный сбой SOCKS5 приостанавливают трафик: текущие туннели закрываются, новые запросы Claude запрещены, процесс сохраняется. Прежний подтверждённый IP возобновляет доступ; недостоверный ответ оставляет шлюз закрытым до успешной перепроверки. Локальные адреса проверяются каждую секунду; изменения маршрута отслеживаются через `NWPathMonitor`.

По умолчанию внешний адрес проверяется каждые 5 секунд; доступны 2, 5, 10, 30 секунд. Тайм-аут повторного запроса — 4 секунды. При настройке 5 секунд обнаружение может занять около 9 секунд. Мгновенная блокировка при смене публичного IP не гарантируется. Прокси с разными выходами для разных сайтов или семейств IP может не пройти строгую начальную проверку.

Периодические внешние проверки можно отключить. Тогда остаются локальные адреса, маршрут и состояние SOCKS5. **Публичный IP за NAT или на стороне прокси невозможно определить только локальными данными.** Ручная повторная проверка всё равно вызывает ipify. Сервисы получают выходной IP; запросы Claude им не передаются.

SOCKS5 подключается через HTTPS CONNECT → SOCKS5 на случайном порту только `127.0.0.1`. Поддерживаются логин/пароль и отсутствие авторизации. Целевые имена передаются SOCKS-серверу; имя самого прокси разрешается локально. До начальной проверки шлюз пропускает только сервисы проверки IP. При сбое он не переходит на прямое подключение.

## Перехват

Данные берутся из Chromium после обработки HTTPS внутри приложения. Рабочая сборка не устанавливает сертификаты и не отключает проверку TLS.

Окно **Трафик** показывает доступные URL, методы, заголовки, текстовые тела, статусы, SSE и текстовые WebSocket-кадры. Записи CONNECT отдельно показывают адрес, состояние и объём зашифрованных данных. Известные поля таймзоны с `Europe/Moscow` и русской локали отмечаются; обычный текст сообщения о Москве не считается метаданными.

В памяти — 200 последних записей, до 32 768 символов каждого текстового направления. Известные токены, Cookie, Authorization и секретные JSON-поля маскируются; query и fragment URL удаляются. Это не универсальный детектор секретов: переписка и произвольные поля могут содержать чувствительные данные. Большие, бинарные и некоторые потоковые ответы могут быть неполными.

## Границы защиты

Guard закрывает собственный шлюз и завершает свою копию Claude и доступные процессы её группы. В macOS это **не системный firewall, Network Extension или VPN**. Независимые прямые соединения на уровне ОС не запрещаются. Основной Node-процесс, native-запросы, отдельные workers, MCP/CLI, обновления, внешний браузер входа и Cowork могут использовать другие маршруты и быть не видны в перехвате. Функции, зависящие от исходных подписей и entitlements, могут не работать в локально переподписанной копии.

При потере pipe адаптер завершает копию; закрытие сокетов Guard закрывает его туннели. Это не заменяет системную блокировку всех процессов и всех путей обхода. Отдельно запущенный оригинальный Claude не контролируется этой сессией.

## Что проверено

На установленном Claude Desktop **3.1623.0**, Electron **44.9.0**, Apple Silicon пройден сквозной тест реального renderer:

- `Intl` вернул `Europe/Amsterdam`, `navigator.language` и locale — `en-US`.
- Локальный HTTPS-сервер получил `Accept-Language: en-US` и JSON с этими значениями через настоящий CONNECT → SOCKS5 → TLS.
- Guard перехватил POST и JSON-ответ с маркером `guard-response-ok`.
- Восемь cross-origin iframe на локальном TLS-стенде создавались и закрывались, сохраняя `Europe/Amsterdam` и `en-US`; основная страница продолжала работать.
- Два вспомогательных окна закрывались во время и после инициализации; Claude оставался запущенным. Версия 0.3 на этом же сценарии завершалась с `Debugger detached: target closed`.
- Перезапуск создал отдельный процесс с новым состоянием IP-политики, без пароля прокси; старый процесс не снял свою блокировку.
- Принудительный выход тестового runtime сохранил причину завершения, доступную после повторного чтения журнала.
- Открыт долгоживущий HTTPS-поток. После изменения наблюдаемого IP с `203.0.113.7` на `203.0.113.8` закрылись поток и шлюз, процесс завершился, шлюз отказал в новом подключении. Ручной стоп и повторный запуск не сняли блокировку.

Это изолированный тест: новый профиль, запрет пользовательской Связки ключей и `securityd`, mock-keychain для тестовых cookies, сеть только loopback. Адреса `claude.ai` и `challenges.cloudflare.com` направлялись тестовым SOCKS только на локальный сервер; реальные серверы Anthropic и Cloudflare не использовались. Проверялся жизненный цикл iframe и окон, а не прохождение настоящего Turnstile. Сертификат закреплялся только в тестовом bootstrap, без установки доверия в macOS. Для вложенной тестовой песочницы выключался внутренний Chromium sandbox; рабочая сборка этот флаг не добавляет.

Смена IP подана управляемым провайдером **только в тестовой сборке**; физический внешний IP Mac не переключался. В контрольном прогоне при интервале 2 секунды блокировка заняла 1165 мс с момента тестовой смены; это не гарантия времени реакции в реальной сети. Синтетические результаты сохранены в `Verification/installed-e2e.json`.

Также пройдены локальные проверки авторизации SOCKS5, предварительной блокировки, отсутствия прямого fallback, разрыва туннелей, RU/неизвестной страны, нормализации IPv6, закрепления IP, блокировки до перезапуска, маскирования секретов и остановки при обнаруженной `Europe/Moscow`. Прохождение настоящей проверки Cloudflare, вход в реальный аккаунт, переписка с Anthropic, внешний SOCKS5, Intel и старые macOS этим стендом не проверены.

## Сборка и распространение

Нужны Xcode Command Line Tools со Swift. Python 3 нужен только для тестов.

```sh
bash build.sh
bash test.sh
# Отдельный тест установленного Claude; создаёт локальную копию в указанной папке:
python3 Tests/installed_e2e.py --work-dir /absolute/path/to/scratch
```

Рабочая сборка не содержит тестовых подмен IP, TLS-доверия и mock-keychain. Комплект содержит только собственный код MIT, приложение и синтетические результаты; файлы Claude не распространяются. У каждого получателя должен быть установлен свой Claude Desktop.

Сборка универсальная arm64/x86_64, с локальной ad-hoc подписью, без нотарификации. Для публичного распространения без предупреждений Gatekeeper нужны ваша Developer ID подпись и notarization Apple. Приложение не связано с Anthropic.

## Обновление проверки IP

В macOS 0.3.3 и Windows 0.5.0 временная ошибка IP-сервиса, уведомление о маршруте и сон закрывают трафик до перепроверки, сохраняя процесс Claude. Прежний IP восстанавливает доступ; подтверждённый новый IP блокирует сессию до перезапуска. Проверки IPv4 и IPv6 больше не чередуются для одного закреплённого адреса. На Windows исправлены гонки отмены CONNECT во время DNS/SOCKS и добавлен WFP-брокер. macOS по-прежнему не включает системный сетевой контейнер.

Windows 0.5.2 назначает Job Object атомарно при создании Claude, закрывая окно до прежнего AssignProcessToJobObject. Таблица маршрутов читается напрямую через Windows API вместо запуска PowerShell: медленная загрузка сетевого модуля больше не блокирует запуск. Добавлены проверки аварии во время запуска, гибели контроллера и сохранения cookie, localStorage и IndexedDB после килл-свитча и повторного запуска.

В Windows 0.5.2 также исправлена потеря cookies при быстром первом килл-свитче: перед первой страницей Guard ждёт сохранения собственного DPAPI-обёрнутого ключа Chromium. Закрытие трафика при смене IP остаётся немедленным после обнаружения; профиль не удаляется.
