# Безопасность и сведения для ИБ

Этот документ описывает фактическую архитектуру, а не сертификацию. Независимый продукт; не является официальным клиентом Anthropic. Формальной модели угроз, независимого сертификационного отчёта и обязательств по SLA в репозитории нет.

## Архитектура и границы привилегий

**Windows.** Интерфейс Electron из локального ASAR работает с `contextIsolation`, sandbox renderer, без Node integration; CSP запрещает удалённые скрипты и сетевые подключения renderer. IPC проверяет отправителя и главный frame. Обычный процесс Guard управляет шлюзом и контроллером. NetworkFence получает повышение через штатный UAC и устанавливает WFP-фильтры для проверенных путей исполняемых файлов частной копии. Он не запускает Claude. GuardHost помещает runtime в Job Object. Изоляция Code добавляет AppContainer без capabilities, CodeHost/CodeGate, проверенные образы и отдельную постоянную Workspace. Ограничение Chat по путям EXE не равно полному контейнеру всего компьютера; обращения через службы ОС и ранее неизвестные программы вне этой границы.

В прямом режиме Windows «Текущая сеть / VPN» kill switch привязывает TCP-сокеты через `localAddress` к локальному адресу фактического контрольного соединения проверки IP (`socket.localAddress`), а не адресу интерфейса default route. Это учитывает VPN с маршрутами `0.0.0.0/1` и `128.0.0.0/1`. DNS-запросы A/AAAA отправляются через UDP-сокеты с такой же привязкой; ошибки и тайм-ауты закрывают CONNECT без системного DNS fallback. На время ревалидации шлюз приложения приостановлен, а пин снят: контрольные соединения заново выбирают маршрут без привязки к старому адресу. После успешных проверок IP и назначений закрепляются вновь захваченные адреса, и лишь затем возобновляется трафик. Изменение сети во время подтверждения оставляет шлюз на паузе. Привязка адреса не заменяет фильтрацию маршрутов ОС: её поведение при исчезновении VPN требует проверки на Windows. SOCKS-режим (и системный upstream-прокси) защищает egress только проверками IP: исходящий выход принадлежит процессу прокси.

**macOS.** SwiftUI-приложение, helper/process group, локальный шлюз и адаптер страниц. Опциональный системный сетевой барьер (включён по умолчанию) закрывает главный обходной путь: копия Claude запускается через цепочку `sudo -n → /Library/PrivilegedHelperTools/claudeproxyguard-drop → GuardHost → Claude`, весь процессный лес получает выделенную группу `_cpguard`, а якорь PF `claudeproxyguard` разрешает этой группе только loopback. Native-код, MCP и Cowork внутри копии физически не могут выйти в сеть мимо шлюза. Хелпер только понижает привилегии (root → вызывающий пользователь + группа барьера), его SHA-256 закреплён в приложении при сборке и сверяется перед каждым запуском, запись sudoers NOPASSWD (`ALL`) закреплена за точными путями, поэтому грант не даёт локальной эскалации. Проверка состояния подтверждает и хеш хелпера, и включённый PF (`Status: Enabled`), и наличие помеченных label правил группы в якоре — при каждом запуске сессии и в каждом цикле контроля; потеря барьера во время сессии приостанавливает трафик как смена маршрута. Установка — одноразовое подтверждение администратора через встроенный в приложение скрипт (никаких временных root-файлов). Остаточные риски барьера: DNS-резолвер macOS (mDNSResponder) и ICMP не принадлежат группе `_cpguard` и не фильтруются якорем (утечки имён назначений на уровне ОС вне границы), а процессы, запущенные вне дерева Guard (через `open`, launchd, Finder), группу не наследуют. Без барьера (осознанное отключение пользователем) остаются задокументированные обходные риски: нативные сетевые вызовы, MCP и Cowork могут обойти прокси. Network Extension, Docker/VM и постоянной службы нет. Нельзя переносить Windows-гарантии на macOS.

Дополнительно на macOS действуют: kill switch привязки исходящих сокетов шлюза (`requiredLocalEndpoint`) к локальному адресу фактического контрольного соединения проверки IP в режиме «Текущая сеть / VPN» — адрес захватывается из `currentPath.localEndpoint` самого соединения, а не из default route, поэтому VPN с маршрутами `0.0.0.0/1` и `128.0.0.0/1` закрепляется за туннельным интерфейсом (исчезновение адреса рвёт новые CONNECT до отправки пакета); на время ревалидации пин снимается, контрольные соединения заново выбирают маршрут, и лишь после успешных проверок закрепляются вновь захваченные адреса до возобновления трафика; синхронная пауза шлюза перед любым ожиданием в catch-ветках ревалидации, обязательный периодический контроль внешнего IP, отказ от mapped-IPv4 ответов DNS и от имён прокси в mDNS-зонах (.local/.lan/.internal), закрепление системного SOCKS-прокси как upstream вместо его обхода и отказ при несовместимом системном HTTP-прокси. Runtime-копия получает харденинг main-процесса: `--disable-quic`, `dns-prefetch-disable`, WebRTC `disable_non_proxied_udp` (заблокировано и изменение политики), `host-resolver-rules MAP * ~NOTFOUND, EXCLUDE 127.0.0.1` (имена разрешает шлюз), запреты Node API `dgram`, `dns`, не-loopback `net/tls/http/https/http2/fetch/WebSocket/EventSource` (включая строковые порты `net.connect("443", host)` и `listen` без явного loopback-адреса), блокировка смены `session.setProxy` и опасных Chromium-флагов. Остаточный риск: системный резолвер macOS для имён назначений (через mDNSResponder) не привязан к egress-интерфейсу — запросы A/AAAA могут обслуживаться вне закреплённого маршрута, хотя сами соединения привязаны.

Оригинал Claude не распространяется и не патчится на месте. Guard готовит отдельную копию и профиль, изменяет её ASAR и целостность. Исходная подпись Anthropic не удостоверяет модифицированную копию. Windows проверяет исходную подпись при подготовке; Code требует точного закреплённого исходника. На macOS результат проверки исходной подписи передаётся в UI как предупреждение и не является безусловным запретом запуска — см. `Source/RuntimePreparer.swift` и `Source/App.swift`.

## Служба и административные права

**Служба Windows отсутствует.** Нет ServiceBase/SCM-реализации, установщика службы, привилегированного постоянного IPC API или маршрутизации сессий через такую службу. `Windows/src/service-integration.cjs` — интерфейс интеграции, недоступный по умолчанию; он не выполняет привилегированные операции. Предусмотренные состояния UI не доказывают наличие backend. Детали: [контракт](docs/service-integration.md).

В текущем Windows-движке повышение требуется для WFP-брокера новой сессии и отдельно для необязательного скрипта блокировки оригинального Claude. Сам Guard не следует запускать как администратор. Portable и пользовательский установщик не отменяют эти требования. Обычный перезапуск интерфейса и последующий защищённый запуск — разные действия; новый защищённый запуск может снова потребовать UAC. Однократное подтверждение установки службы станет возможно только после отдельной реализации и проверки backend/движка.

## Сеть, порты и зависимости

- Локальный HTTP CONNECT-шлюз слушает случайный TCP-порт **127.0.0.1**. Нет фиксированного публичного порта или сервера удалённого управления.
- Управление копией: закрытые Windows named pipes либо унаследованные pipe/stdio на macOS; внешний TCP debug-порт не открывается.
- Проверки IP/страны: HTTPS `ipwho.is`, `api64.ipify.org`, `api.ipify.org`, `api6.ipify.org`; Windows также проверяет служебные `/cdn-cgi/trace` адреса `claude.ai` и `api.anthropic.com`. Эти серверы видят выходной IP и обычные сетевые метаданные, но Guard не отправляет им чат и данные аккаунта.
- При включении Code Windows может загрузить закреплённый CLI 2.1.304 с `downloads.claude.ai` через Guard; размеры и SHA-256 проверяются. Комплекты Git/PowerShell включаются при сборке из отдельно проверенных sidecar ZIP.
- Claude, его вход, файлы и Code могут обращаться к другим узлам. Приведённые домены — зависимости проверок Guard, **не исчерпывающий allowlist трафика Claude**.
- В SOCKS5-режиме целевые имена передаются прокси; имя самого прокси может разрешаться локально. В режиме текущей сети Guard использует текущий маршрут/поддерживаемый статический прокси Windows. Guard сам имеет сеть для работы шлюза. Настройки прокси/VPN задаёт пользователь. В режиме текущей сети/VPN на macOS шлюз ограничивает адреса назначения семейством проверенного IP-адреса.
- Сертификаты MITM не устанавливаются, TLS-проверка в production не отключается. Видимые веб-данные берутся внутри доступных контекстов Claude после TLS, а не расшифровкой чужого TLS на маршруте.
- Локальный шлюз слушает только IPv4 loopback со случайным портом сессии, но не аутентифицирует клиентские соединения: любой локальный процесс, нашедший порт во время разблокированной сессии, может использовать настроенный маршрут Guard. На компьютерах с посторонними пользователями и непроверенным ПО это учитывайте отдельно.

У Windows-брокера BLOCK-фильтры сохраняются при аварии/обрыве канала; штатное удаление требует подтверждённого завершения runtime. Это может оставить ограничения после некорректного выхода. Отключение системного Firewall и удаление всех WFP-фильтров не являются способом штатного восстановления.

Проверка внешнего IP периодическая и зависит от внешних серверов. Между сменой удалённого NAT и обнаружением есть интервал. Нулевое количество утекших пакетов, мгновенное закрытие каждого сетевого соединения и доступность сервиса Claude не гарантируются.

## Данные, секреты и журналы

**Windows:** `%APPDATA%\Claude Proxy Guard\Guard`: `settings.json`, `diagnostics.json` (до 80 событий), `Profile`, runtime/cache, CodeAssets/CodeBin/CodeTools и `CodeState\Workspace`; данные авторизации Code находятся внутри CodeState. Пароль SOCKS5 исключается из сохраняемых settings и остаётся в памяти. Имя прокси, порт и логин сохраняются. Сеансовые токены IPC передаются только локально и не предназначены для экспорта.

**macOS:** `~/Library/Application Support/ClaudeProxyGuard` содержит Profile, Runtime, `Diagnostics/events.jsonl` (до 80 событий) и временные `guard-env-*` файлы окружения сессии (0600, удаляются при завершении); настройки — UserDefaults домена `local.proxyguard.claude`. Барьер добавляет системные компоненты: `/Library/PrivilegedHelperTools/claudeproxyguard-drop` (root:wheel), `/etc/sudoers.d/claudeproxyguard`, `/etc/pf.anchors/claudeproxyguard`, две строки между маркерами в `/etc/pf.conf` и группу `_cpguard`; все они удаляются штатной деинсталляцией барьера. Пароль прокси не сохраняется настройками. Runtime-профиль самого Claude может хранить собственные cookies/данные входа; их поведение определяется также vendor runtime. Guard не переносит прежние Keychain-учётные данные для клонирования профиля.

Трафик ограничен 200 записями в памяти, экспортируется по явному действию пользователя. Windows по умолчанию не захватывает тела; macOS по текущему коду включает captureBodies по умолчанию, если нет сохранённого значения. Маскирование известных секретов и IP в диагностике не является универсальным DLP. URL, заголовки и произвольные поля/тела могут оставаться чувствительными; сырой экспорт нужно проверять перед передачей. Собственного шифрования профилей, экспорта и настроек на диске нет. POSIX `mode` в JS сам по себе не является доказательством Windows ACL; Code ACL настраивается отдельным механизмом движка.

## Телеметрия

В коде Guard нет отдельного аналитического SDK/сервера телеметрии. Проверки IP, загрузка CLI, трафик Claude и действия входа являются реальными внешними передачами данных. Собственные телеметрия и обновления vendor Claude/Code этим утверждением не исключаются. Для подготовленного PowerShell выставляются `POWERSHELL_TELEMETRY_OPTOUT=1` и `POWERSHELL_UPDATECHECK=Off`; это не отключение всей телеметрии ОС и сторонних приложений.

## Происхождение сборок и подписи

Проверяйте release/tag, source commit, SHA-256 каждого артефакта и список выполненных проверок. ZIP не должен содержать Profile, settings, ключи подписи, токены, Claude Desktop или тестовые профили. Пакеты Git/PowerShell имеют отдельную политику исходников и хешей. Контрольная сумма с той же страницы помогает проверить целостность, но не является независимой подписью издателя.

Настроенной Authenticode-подписи Windows/установщика и подтверждённой Developer ID/notarization macOS нет. `build.sh` применяет **ad-hoc** codesign к бандлу и helper. Это локальная целостность, не подтверждение издателя Apple. Подписание сертификатом организации и нотариализация требуют отдельной настройки; секреты не должны храниться в Git или пакетах. Приложение не имеет заявленных сертификатов ИБ и не обещает прохождение корпоративных проверок.

## Полное удаление и остаточные правила

Следуйте [инструкции эксплуатации](docs/operations.md#полное-удаление). Удаление portable-папки или деинсталляция программы не означает удаление пользовательского профиля, рабочих файлов, зарегистрированных ссылок или оставшихся после аварии политик. Постоянной службы для удаления в этой версии нет. Для будущей службы API удаления пока отсутствует — UI не делает вид, что очищает её.

## Сообщение об уязвимости

Используйте приватное сообщение об уязвимости на вкладке Security репозитория, **если эта функция включена владельцем**. Её доступность не подтверждена как обязательный канал. Если приватного канала нет, создайте публичный issue только с просьбой организовать приватный контакт, без exploit, токенов, профилей и переписки. Отдельный security email, PGP-ключ, гарантированный срок ответа и bug bounty в проекте не настроены.

Для воспроизведения пригодны версия/commit, платформа/архитектура, минимальный синтетический пример, ожидаемое и фактическое поведение. Удалите IP, URL входа, данные аккаунта и тела запросов. Авторы должны подтвердить исправление на затронутой платформе; недоступные проверки обозначаются NOT RUN.

Проверочные и контрольные назначения требуют токен текущей сессии; выходные IP claude.ai и api.anthropic.com закрепляются и проверяются так же, как основной IP.

На macOS статическая конфигурация системного прокси проверяется и закрепляется за сессией; подтверждённое изменение закрывает сессию до перезапуска Guard.

## Постоянная память IP (Windows 0.6.15 / macOS 0.3.8)

`ip-memory.json` хранит единственный проверенный внешний IP независимо от сессии и браузерного профиля. До открытия прикладного трафика общий IP и служебные маршруты Claude должны совпасть с ним; первая запись выполняется после всех проверок. Запись атомарная с синхронизацией и повторным чтением. Повреждённые, слишком большие и связанные файлы не принимаются. Подтверждённый сброс после остановки пишет пустое закрепление; перезапуск сам по себе его не сбрасывает. Это политика приложения, а не защита от пользователя, который изменяет или удаляет собственные данные на диске.

Системные ограничения WFP/PF сохранены. Guard не устанавливает TUN для всей ОС. Наличие TUN само по себе не доказывает закрытие DNS/WebRTC: глобальный VPN и его отказоустойчивость проверяются отдельно. Интервал обнаружения удалённой смены IP сохраняется.
